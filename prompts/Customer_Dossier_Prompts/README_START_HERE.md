# Customer Dossier — пакет промтов для развития локального портала

**Редакция:** 11.09.2026, v1.0.  
**Рабочий режим пользователя:** Claude Opus 5 (1M), Claude / Cursor; Codex — дополнительная независимая проверка.  
**Формат:** 10 этапов 00–09, разбитых на 13 последовательных промтов реализации; отдельные промты проверки, исправления и передачи контекста.

## Что строим

Локальный портал для ответа на вопрос: «К нам обратилась компания по конкретной стройке. Кто это, какую роль она выполняет, с кем связана, что известно о её опыте и текущем фоне и что необходимо уточнить?». Сбор из согласованных публичных Telegram-каналов и обозначенных сайтов. Выводы должны открываться до точной версии публикации и цитаты. «Не установлено» — нормальный результат; отсутствие новостей не означает надёжность.

Это **пакет заданий, а не обновлённый код**. Его проверка не означает, что этапы уже реализованы. Прежние исправления из архива reviewed — только возможная стартовая база: локальный код сначала проверяет этап 00.

## Начало работы

1. Распакуйте папку `Customer_Dossier_Prompts` в `prompts/` внутри вашей текущей рабочей папки проекта. Получится `prompts/Customer_Dossier_Prompts/`. Код проекта поверх рабочей папки из другого архива не копируйте.
2. Откройте именно корень проекта в привычном инструменте, которому доступно чтение и изменение локальных файлов. Выберите используемую вами модель. Название и окно контекста в этом пакете — ваша конфигурация разработки, а не инструкция менять модель самого портала.
3. Отправьте стартовый промт ниже. Он разрешает только этап 00: исследование и отчёты. Затем по одному отправляйте промты из таблицы. После завершения каждого этапа прочитайте отчёт и результат проверки.

### Первый промт — скопируйте целиком

```text
Работаем над локальным Customer Dossier. Пакет заданий находится в
prompts/Customer_Dossier_Prompts/.

Прочитай README_START_HERE.md, COMMON_RULES.md, ROADMAP.md,
reference/REPOSITORY_MAP.md и stages/STAGE_00_BASELINE.md из этой папки.
Проверь фактическую рабочую папку, существующие инструкции и незакоммиченные изменения.
Выполни только STAGE_00_BASELINE.md. Код приложения, рабочую БД, настройки
секретов и источников пока не меняй. Допускаются только отчёты в docs/development/.
Не запускай портал, миграции, сбор или переизвлечение до проверки их побочных действий.
Не считай предыдущий reviewed-архив установленным, а старые отчёты — доказательством тестов.
После отчёта и handoff остановись. К этапу 01 самостоятельно не переходи.
```

### Следующий этап — пример для 01

```text
Прочитай prompts/Customer_Dossier_Prompts/COMMON_RULES.md,
docs/development/STATE.md, актуальный HANDOFF.md и отчёт этапа 00.
Проверь, что необходимые входные условия этапа 01 выполнены фактически.
Выполни только prompts/Customer_Dossier_Prompts/stages/STAGE_01_LOCAL_SAFETY.md.
Это разрешение на изменения кода и тестов внутри этого этапа, но не на изменение
моей рабочей БД, подключение новых источников, commit/push или публичное размещение.
Проведи предусмотренные проверки, запиши отчёт и остановись.
```

Для последующих шагов заменяйте путь последним нужным именем из ROADMAP. Не отправляйте «сделай все этапы». `ALL_STAGE_PROMPTS.md` — сводный справочник, не одно задание на исполнение.

## Как использовать Claude, Cursor и Codex

**Основной режим:** одна сессия-исполнитель меняет код. Cursor используйте как рабочую среду и для просмотра изменений. Codex или свежую сессию Claude подключайте как проверяющего по `service/REVIEW_STAGE.md`, без правок того же дерева одновременно. При обнаруженных дефектах возвращайте список основному исполнителю через `service/FIX_REVIEW.md`.

Не нужно одновременно запускать три пишущих агента. Параллельные помощники, если доступны, исследуют разные области только для чтения. Нет таких инструментов — выполняйте последовательно. Не предполагается наличие конкретной подписки, автоматического переключения моделей или команды для принудительного включения 1M.

Переход в свежую сессию: `service/RESUME_STAGE.md`. Передача текущей работы: `service/WRITE_HANDOFF.md`. Нужна только оценка плана до правок: `service/REVIEW_PLAN.md`.

## Что специально не включено в первую локальную версию

Публичное развёртывание, SSO, многопользовательский SaaS, сложная ролевая модель, Kubernetes, Redis/Kafka, отдельная графовая БД, платные внешние проверки, дообучение, массовый OCR и обработка закрытых Telegram-каналов. Для локальной работы достаточно одного оператора, но нужны защита изменяющих API, запрет произвольных сетевых адресов, раздельный допуск сбора и ИИ, сохранность данных и резервная копия.

Модель, которой вы **пишете код**, не обязана быть моделью, которой портал **обрабатывает публикации**. Текущий локальный LLM-провайдер не заменяется на облачный автоматически. GPU, доступный контекст и лимиты runtime устанавливаются по вашей машине, а не по 1M у инструмента разработки.

## Честность результатов

PASS означает реально выполненные обязательные проверки. NOT_RUN не равен PASS. Отдельно фиксируются: реализация адаптера на фикстурах, проверка локальной моделью и проверка каждого живого источника. Отсутствие разрешённого канала не блокирует работу над локальным досье, но такой канал нельзя объявлять подключённым.

Сводка проверки самого пакета — `PACKAGE_CHECK.md`. Источники и границы исходного анализа — `reference/`.
