# Общие контракты данных и смыслов

Это целевой контракт для согласованного исполнения этапов, **не утверждение о существующих таблицах**. На первом затрагивающем этапе выбери физическую схему, запиши ADR в docs/development/ и затем сохраняй названия/семантику между этапами. Не создавать по новой реализации «свой» SourceItem, Assertion или Review при каждом запуске.

## Слои и ответственность

| Слой | Что хранит | Что не делает |
|---|---|---|
| Source | Площадка, ключ/адрес, допуск операций, состояние и регламент | Не объявляет сбор допустимым только по доступности URL |
| SourceItem | Устойчивая личность конкретной публикации | Не объединяет публикации разных источников по content hash |
| DocumentRevision | Неизменяемое наблюдаемое содержимое, версия, полнота | Не переписывает старый текст и цитаты |
| ExtractionRun/Chunk | Происхождение машинного ответа и покрытие входа | Не превращает partial в complete |
| Mention | Конкретное упоминание в тексте и candidate identity | Не объединяется по одному имени без контекста |
| Assertion/version | Смысл: субъект, отношение/значение, объект, период, модальность | Не объявляет сообщение источника установленной истиной |
| Evidence | Конкретная revision + span + supports/contradicts + источник происхождения | Не выдумывает независимость перепечаток |
| ReviewDecision | Кто и что проверил, основание и версия на момент решения | Не удаляется и не переносится молча на изменённый смысл |
| Entity/Identifier | Legal entity / brand / group, реквизит по типу и стране | Не сливает бренд с ООО без основания |
| Project/Participation | ЖК/очередь/корпус, роль/работы/период | Не переносит роль на все объекты компании |
| Relation/Event | Типизированная связь или событие со сторонами и временным смыслом | Не создаёт транзитивный договор/вину по общему участию |
| Read-model | Детерминированное представление опубликованных сведений | Не использует собственную скрытую базу «фактов» |
| DossierCase | Конкретное обращение, предмет и заявления оператора/контрагента | Не делает введённое заявление подтверждённым фактом |
| DossierSnapshot | Зафиксированный payload и доказательная база выбранного среза | Не регенерируется при каждом открытии |

## Статусы: не использовать одно поле confidence для всего

- Техническая обработка: queued/running/partial/failed/complete; публикация candidate/active/superseded отдельно.
- Полнота текста: full/excerpt/caption_only/failed/unknown. Полный разбор excerpt остаётся полным разбором **анонса**, а не полной статьи.
- Проверка: candidate/text_grounded/reviewed_supported/disputed/rejected; дополнительно needs_revalidation при изменении основания. Grounded — «есть в тексте».
- Смысл: polarity positive/negative; modality reported_fact/claim/planned/possible (финальные enum согласовать); review и modality не подменяют друг друга.
- Допуск source: отдельно access и ai_processing, unknown/approved/blocked/revoked/expired; retained/display/export scope учитывать отдельно по действующей политике.
- Исходные Confidence модели — диагностические поля без обещания вероятности истины.

Старый `status=auto` переносится как auto/legacy_unreviewed, не как reviewed. Человек может подтвердить корректность отражения заявления, не утверждая истинность самого обвинения; UI должен сохранить этот объём решения.

## Временная модель

UTC для timestamp хранения, исходный timezone/offset при наличии и настраиваемое отображение. Пользовательский часовой пояс Europe/Amsterdam не подставляется как пояс всех российских публикаций. Date-only хранится как date, не превращается в соседний день при UTC-конверсии.

Раздельно: published_at, source_modified_at (если известно), fetched_at/observed_at, occurred_at/from/to с precision, valid_from/to отношения, recorded_at версии/решения, reviewed_at. Unknown не становится now. Для квартала/месяца — интервал/precision, а не фиктивный точный день.

Снимок имеет generated_at; knowledge_cutoff — что было известно/записано до момента; effective_date_filter — к каким событиям/ролям относится вопрос. Фильтр событий «за 2025» при сегодняшнем знании не является справкой, реально имевшейся в 2025. Нет достаточной истории legacy — историческая реконструкция помечается неполной.

## Идентификаторы и значения

Каждый реквизит хранится по типу (ИНН, ОГРН и т. д.), стране и строке без потери ведущих нулей. Домен/телефон/название — не уникальный юридический ID. Валидация формата/контрольной суммы отделена от evidence о принадлежности. При known conflict auto-merge запрещён.

Сумма: decimal в БД и строка/API decimal codec, currency, units/scale, purpose, tax basis, evidence. Число в источнике может быть количеством квартир или суммой иска, а не стоимостью договора. Нет признака НДС — unknown; не использовать какой-либо процент пользователя из другого проекта.

Project hierarchy и work package значимы для связи. Разрешённые исходные темы работ: общестрой, ОВ, ВК, ЭОМ, СС, автоматика, противопожарные системы и иные подтверждённые текстом. Свободный исходный label можно сохранять рядом с нормализованным; неизвестный пакет остаётся null.

## Evidence и происхождение

Выбери один документированный контракт offsets, например [start, end) в UTF-16 code units строки, реально сохранённой для extraction. Нужна однозначная связь с immutable representation/hash и transform version. Если для raw/clean text требуется mapping — сохраняй его. Не объявлять проверенную цитату сырого HTML при наличии только cleaned-text offsets.

supports и contradicts не взаимоисключающие для одного набора evidence: противоречия должны быть видны. Repost cluster != independent sources count. Первичность, независимость, качество источника и текстовое совпадение — разные признаки; unknown первичность сохраняется.

Manual review привязан к конкретному содержанию assertion и evidence set на дату. Новый смысл создаёт версию/новое утверждение. Отзыв одного evidence сохраняет чужие evidence и историю решения, но может менять актуальность подтверждения. Правки текста источника не заменяют старую quote.

## Переизвлечение и совместимость

run append-only → candidate set → preview → атомарный promotion с expected generation → совместимая проекция. Active-set pointer и legacy read adapter лучше двух независимых writers. Старый destructive apply не работает параллельно новому. DB-транзакция не держится во время сетевого LLM-запроса.

Уникальности должны отражать предмет: два дела одной компании не уникальны по type+company+project; два пакета работ не уникальны по company+project+role без контекста. В неоднозначной дедупликации сохранять candidates/очередь, а не терять строки через ON CONFLICT DO NOTHING.

## Ограничения продукта

Прямой договор не следует из общего ЖК; корпоративное владение не следует из общей новости; событие на объекте не доказывает вину участника. Система не формирует рейтинг кредитоспособности или автоматическое решение о сотрудничестве. «Не найдено в имеющейся выборке» корректнее «отсутствует».

Минимальная версия работает локально на PostgreSQL без сети после сохранения данных. Не требуется cloud API, новый runtime LLM, графовая СУБД, SSO или система продаж. Private source/personal surveillance не часть задачи.
