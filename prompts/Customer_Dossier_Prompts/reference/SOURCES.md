# Источники и границы проверки

**Проверено при подготовке пакета: 11.09.2026.** Технические характеристики инструментов и правила площадок перепроверяются в момент реального подключения. Пользователь запросил пакет под свой режим «Claude Opus 5 (1M)»; пакет не устанавливает model ID, не проверяет аккаунт и не обещает доступность 1M в конкретном интерфейсе. Режим указан пользователем, runtime портала остаётся отдельной настройкой.

## Первичные документы

[S1] Anthropic, Best practices for Claude Code.  
https://code.claude.com/docs/en/best-practices

Применён общий подход: предварительное исследование, ограниченное задание, проверяемый результат и отдельная проверка. Дорожная карта и предметные тесты этого пакета — проектные решения, а не готовая архитектура из документации Anthropic.

[S2] Anthropic, How Claude remembers your project.  
https://code.claude.com/docs/en/memory

Используется идея кратких постоянных правил и явно читаемых файлов проекта. Пакет не заменяет существующий CLAUDE.md автоматически и не гарантирует, что правила были прочитаны, без проверки исполнителем.

[S3] Anthropic, Create custom subagents.  
https://code.claude.com/docs/en/sub-agents

Субагенты, если инструмент их предоставляет, могут изолировать исследование. Пакет не требует их наличия: последовательное исполнение допустимо. Роли Cursor/Codex в пакете — предложенная организация работы пользователя, не заявление об автоматической интеграции продуктов.

[S4] Anthropic, Context windows.  
https://platform.claude.com/docs/en/build-with-claude/context-windows

Окно и доступность модели зависят от интерфейса/настройки. Здесь не фиксируются тарифы, API headers или непроверенные CLI-опции для включения 1M.

[S5] Telegram, Terms of Service for Content Licensing.  
https://telegram.org/tos/content-licensing

Условия содержат ограничения на сбор/использование контента для ИИ и отдельное исключение при требуемом согласии. Нельзя считать публичность канала достаточным основанием. Пакет предусматривает реестр допуска, но не выдаёт юридическое заключение о конкретном канале и не оформляет согласования за пользователя.

[S6] Telegram Bot API, Getting updates / Update.  
https://core.telegram.org/bots/api#getting-updates

API предусматривает доступные боту обновления и ограниченное хранение неполученных обновлений (в проверенной документации — не дольше 24 часов). Возможности бота и доступа к истории необходимо проверять отдельно. Промты не обещают чтение ботом любого публичного канала или универсальное наблюдение удалений.

[S7] OWASP, Server Side Request Forgery Prevention Cheat Sheet.  
https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html

При реализации клиента источников учитываются allowlist, проверка адресов и перенаправлений, различение доверенных служебных endpoints и произвольных внешних URL. Конкретное безопасное исполнение зависит от выбранного HTTP-клиента и требует тестов, а не только regex.

## Данные самого проекта

`ORIGINAL_REVIEW_2026-09-11.md`, `ORIGINAL_SPEC_2026-09-11.md` — копии предыдущих материалов пользователя/ассистента из этой беседы. Они сохранены как historical reference, не как новые тестовые результаты. Разделы о полном RBAC/публичной эксплуатации не являются блокирующим требованием текущей локальной версии; актуальный scope — COMMON_RULES и stages.

`REPOSITORY_MAP.md` — дополнительно прочитанные точки кода из приложенных архивов. `ARCHIVE_FINGERPRINTS.json` — контрольные хеши входных файлов. Архив проекта и patch намеренно не включены внутрь промт-пакета, чтобы случайно не перезаписать локальную работу.
