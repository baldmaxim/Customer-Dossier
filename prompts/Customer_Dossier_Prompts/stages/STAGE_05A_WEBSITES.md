## Цель

Получать тексты и карточки объектов с сайтов, которые обозначены пользователем, а не обещать поддержку HTML на основании неиспользуемого listSelector. Каждый источник имеет собственный проверенный профиль и состояние готовности.

## Список источников

Прочитай имеющийся реестр и обезличенную конфигурацию. Раздели: approved и настроен; disabled/unknown; отсутствует в актуальном списке. Seed-строка и название домена не означают согласование пользователя. Не добавляй случайные сайты для демонстрации. Если живых approved сайтов нет, реализуй адаптеры на включённых/синтетических HTML/RSS-фикстурах и не блокируй весь этап; выставь `LIVE_SOURCE=NOT_RUN`, не «подключено».

## Адаптеры

Реализуй чёткий контракт `discover → fetch → parse → persist/observe`: RSS/Atom, HTML-список с пагинацией, полная статья, карточка строительного объекта. Конфиг типизируется и валидируется: allowed_hosts, стартовые страницы, селекторы, пагинация, date locale/timezone, canonical rules, пределы страниц/байт/времени. Не позволяй JS/eval/произвольный shell в настройке источника. HTML-парсер остаётся в существующем стеке; headless-browser добавлять только при доказанной необходимости конкретного разрешённого сайта, не как default.

Полный текст не определяется количеством символов анонса. RSS content может быть full только по явному контракту источника/признакам, иначе fetch детальной статьи. Неудача fetch сохраняет excerpt с ограничением, не маскируется как full. Карточка объекта — версионируемый item с участниками/статусом и датой наблюдения; статическую страницу не выдавай за новую новость каждый день.

Даты без года/часового пояса не дополнять скрыто: documented parsing rule + precision/uncertainty. Изменение raw layout при том же текстовом содержании — observation/parser_version, а не ложное бизнес-событие. Обрезанные блоки, неподдержанные таблицы/PDF/сканы отмечаются явно. Вложения не скачивать рекурсивно и не заявлять разобранными.

## Догоняющий обход

Курсор продвигается после надёжного сохранения подтверждённого диапазона. При пагинации, сетевом сбое и повторном запуске не пропускаются доступные страницы. Ограничения источника и pagination exhaustion видны в coverage, невозможно гарантировать полную историю при неизвестной структуре. Учитывай retry_after/backoff и conditional requests при поддержке; 304 — наблюдение без новой revision. Ошибка DNS/429/403/политики различаются; 403/CAPTCHA не обходить прокси-ротацией и аккаунтами.

Пустой результат отличай от parser_degraded. Если раньше известный профиль внезапно не находит article/list/title, виден warning и контрольный счётчик; «новостей нет» не выдаётся автоматически. Лимит запросов/страниц не означает полное покрытие. Все URLs проходят безопасный клиент этапа 01, в том числе найденные ссылки и redirects. Проверки локального test HTTP server осуществляй через отдельную внедрённую test transport, не ослабляя production policy.

## Админка и наблюдаемость

Покажи source health, last_success, last_attempt, parser_version, задержку, интервалы покрытия, found/saved/changed/skipped/failed и причину. Добавь dry probe конкретного already-approved источника с ограничением объёма. Probe не включает постоянный scheduler и не меняет policy. В обычном локальном режиме сети по умолчанию нет.

## Приёмка

RSS анонс → полная статья; HTML-list без RSS; pagination с падением второй страницы; изменение статьи; повтор без дублирования; 304; query-sensitive canonical URL; отсутствие селектора; слишком большой ответ; 429; redirect вне allowlist; недоступная полная статья и честный excerpt. Тесты source→revision идут через реальные сервисы хранения на тестовой PostgreSQL. Для каждого реально проверенного домена отдельный протокол, без общего «все сайты поддержаны».

## Вне этапа и откат

Telegram, массовый OCR, снятие антибот-защиты и общий web-crawler не входят. Fallback — pause конкретного источника с сохранением текста/версий. Не удалять предыдущие данные при поломке парсера.
