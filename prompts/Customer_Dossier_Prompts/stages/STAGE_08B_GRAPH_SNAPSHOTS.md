# Этап 08B — Доказательная схема связей, снимки и экспорт

Ты — основной инженер Customer Dossier. Выполни только этот этап в существующем локальном проекте.

## Перед началом

Прочитай `COMMON_RULES.md`, `ROADMAP.md`, `reference/DATA_CONTRACTS.md`, `acceptance/TEST_MATRIX.md` из пакета. Проверь реальные инструкции репозитория, `docs/development/STATE.md`, `HANDOFF.md` и отчёты зависимостей: **08A**. Отсутствующий отчёт не придумывай. Источник истины о реализации — рабочие файлы и фактические тесты.

Ниже приведены пути из inspected-архива. Если структура изменилась, найди эквиваленты поиском внутри проекта и зафиксируй соответствие, не создавай дубликаты модулей.

## Обязательные точки чтения

Case/dossier API и UI этапа 08A; типизированные связи и read-model; ReviewDecision/Evidence/Revision; merge mapping; `frontend/vite.config.ts` и политика кэша. `reference/DATA_CONTRACTS.md`, раздел о датах среза.


## Цель

Показать связи понятной схемой и зафиксировать досье так, чтобы его содержание не менялось вслед за новой новостью, слиянием компаний или новой моделью. Реализуй локальные экспортируемые материалы, а не только кнопку-заглушку.

## Схема связей

Узлы: юридические лица/бренды/группы и объекты с корпусами. Рёбра имеют тип, направление, объект/пакет работ/период и статус. Договорные, корпоративные и информационные связи визуально и текстом различаются; co_mentioned по умолчанию скрыто. Не использовать толщину/цвет как вероятность надёжности. Путь А→Б→В не рисует прямого договора А→В.

Фильтры: проект/корпус, период, тип связи, только проверенные/включая сообщения, глубина и лимит узлов. Ограничивай запросы и рекурсивный обход, обрабатывай cycles. Вместо нечитаемого «облака» — приоритет текущему обращению и раскрытие соседей. Есть табличная альтернатива для доступности и больших графов. Выбор ребра открывает exact evidence/revision/quote и противоречия. Не создавай отдельную графовую БД. Библиотека визуализации — минимальная, с объяснением причины и проверенной совместимостью; текущий стек предпочтительнее.

## Снимок

Создай DossierSnapshot с immutable payload, schema_version, case_id, generated_at, data_cutoff/knowledge_cutoff, effective-date filter, rules version, selected assertion/evidence/review IDs и воспроизводимыми labels. Если summary создаёт модель, хранить готовый текст + provenance/config fingerprint; повторный просмотр не генерирует его заново.

Различай: «что система знала к дате T» и «события за период T, которые мы знаем сейчас». Создание исторического knowledge-as-of требует реальных recorded_at/history; если legacy не хранит нужную историю, не обещай точный срез прошлого. Снимок, созданный сегодня, воспроизводим с этого момента; старый effective_date filter не превращает его в документ, существовавший в прошлом.

Снимок хранит замороженную структуру/формулировки/разрешённые цитаты и ссылки на точные revision. Одних FK на mutable company name/active review недостаточно. Merge/новая публикация/пересчёт метрик/переименование компании не меняют payload старого снимка. Сохраняй hash по явно определённой canonical serialization; hash показывает целостность payload, не нотариальную/квалифицированную подпись и не истинность фактов.

Права на хранение/выдачу продолжают действовать: при отзыве доступа не раздавать snapshot в обход policy. Раздели immutable content и current availability/revocation state. При обязательном удалении защищённых фрагментов действуй по утверждённой политике, сохраняя разрешённые tombstones; не обещай «никогда нельзя удалить» вопреки правилам. Экспорт не делает сайт-источник свободным для перепубликации.

## Экспорт

Обязательный минимум: Markdown, JSON и самодостаточная HTML-версия для локальной печати в PDF через браузер. Это не равно нативному серверному PDF-export; подпиши действие честно «Версия для печати». Нативный PDF можно отложить без провала этапа. Не добавляй cloud render service и обязательные внешние шрифты. Все выгрузки строятся из выбранного snapshot, не из текущей БД.

Включи заголовок, компанию/реквизиты, предмет обращения, дату создания/среза, существенные выводы, таблицы ролей/событий, вопросы и ограничения, список источников с цитатами/версиями. Escape/sanitize HTML/Markdown-ссылки, разрешённые URL schemes; в экспорт не попадают tokens, stack traces и технический контекст модели. HTML не исполняет scripts и не тянет внешние ресурсы. JSON имеет явно документированную схему и decimal strings. При выдаче защищённого экспорт-файла проверяй доступ; не клади его в публичную static папку.

## Приёмка

Построй snapshot S1 → измени исходную публикацию/имя компании/merge/rules → S1 показывает прежний payload, S2 — новое состояние. Сохрани различие knowledge/effective dates. Review conflict и missing evidence отражаются в снимке. Graph не делает транзитивный договор. Каждый edge и важное предложение открывает основания. Экспорт HTML/MD/JSON совпадает по существенному содержанию, работает без сети и не исполняет вредоносный фрагмент источника. Проверяй доступ после logout и отзыва source policy. Распечатка не обрезает таблицы/русский текст, если доступен браузер.

## Откат

Отключить новые graph/export routes, не изменяя ранее созданные snapshots. Недоступный evidence показывает понятное ограничение, а не заменяется цитатой из свежей версии. Рассылка досье внешним адресатам не входит в этап.

Перечисли изменения файлов, новые миграции, активные флаги, остаточные риски и инструкции безопасного отката. Не меняй рабочую БД и не включай новые источники. Остановись после этого этапа; следующий промт должен отправить пользователь.
