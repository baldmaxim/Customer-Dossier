## Установка пакета
Распаковать папку в `prompts/TG_Info_Next_Stages_2026-09-16/` внутри своего проекта. Не заменять корневой `CLAUDE.md`, исходники и прошлые отчёты содержимым этого архива. Предыдущий набор промтов оставить как историю.

Открывать IDE из корня приложения. Один агент редактирует код, второй в это время не меняет те же файлы. Для ревью передавать зафиксированный diff либо точный список локальных изменений. Commit/push — только по действующему разрешению владельца, этот пакет его не выдаёт.

## Обычный цикл одного этапа
Прочитать один промт → проверить актуальный код → воспроизвести дефект → сделать небольшой diff → выполнить разрешённые проверки → отдать Codex [задание ревью](service/REVIEW_CODEX.md) → исправить подтверждённые замечания → передать пользователю команды запрещённых агенту проверок → записать реальный результат.

Статусы `CODE_READY`, `REVIEWED`, `USER_VALIDATED` отдельные. `NOT_RUN` не означает PASS. Переход к зависимому изменению допустим лишь после необходимого ему gate. Независимые офлайн-задачи не должны бесконечно ждать допуска к источникам, но ожидание нельзя скрывать в общем «всё готово».

`ALL_STAGE_PROMPTS.md` — удобная сводная копия для чтения, **не команда выполнить все этапы сразу**.
