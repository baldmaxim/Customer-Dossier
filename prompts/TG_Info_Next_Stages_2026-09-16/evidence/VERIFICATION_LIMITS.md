# Что проверено, а что нет

## Проверено автором пакета
Распаковка ZIP без выходящих путей; чтение актуального кода/отчётов; source-level синтаксис 222 TS/TSX и транспиляция 220 (две declaration files); 830 относительных import-путей. 10 воспроизведений R01–R10 и положительный контроль C01 на синтетических структурах, часть с mocked dependency.

Скрипт запускает выбранные функции репозитория в одном Node-процессе с ограниченными import. Это не security sandbox для неизвестного кода. Скрипт предназначен только для просмотренного исходного архива; не использовать как разрешение выполнять любой чужой репозиторий.

## Не выполнено здесь
Полный backend/frontend typecheck/build, Vitest suite, PostgreSQL, migrations, Docker, browser, LM Studio, HTTP app и живые источники. `npm ci --ignore-scripts --no-audit --no-fund --fetch-retries=0 --fetch-timeout=15000` завершился неуспешно: EAI_AGAIN registry.npmjs.org; зависимости не установились. Проверки с БД/конкуренцией не имитируются статусом PASS из unit mocks.

User results 421/196, dump/restore и API из docs — сведения самого архива с датой 16.09.2026. Здесь они не воспроизведены. Raw `benchmark-06.json` отсутствует, причина конкретного safety fail не установлена.

## Повторить изолированные наблюдения
Нужна уже установленная TypeScript dependency. Скрипт ничего не устанавливает, не читает .env и не подключает DB/provider; output — JSON в указанный путь. Корень приложения должен быть явным.
```text
node <package>/evidence/audit_checks.cjs <repo-root> <output-json>
```
При необходимости `TG_INFO_TYPESCRIPT_PATH` указывает на имеющуюся локальную папку пакета TypeScript; глобальная установка не запускается. В рабочем репозитории предварительно просмотреть script и diff.

`reproduced=true` означает, что исходный дефект наблюдается. Это **не зелёный тест исправленного продукта**. После исправлений отдельные probes могут перестать соответствовать контракту и требуют адаптации; правильное поведение закрепляется штатными regression tests. Не добавлять этот скрипт в CI как доказательство production-ready.

R08 mock подтверждает ранний replay branch, но не эксплуатацию чужой сессии. R09 mock показывает отсутствие проверки между вызовами, но не гарантированную отмену in-flight. R10 mock показывает отсутствие проверки recorded execution identity, но не замер реальной смены LM Studio модели. F08 — статическая гипотеза смешанного чтения, требует настоящего DB barrier test.
