# sharp — точечная проверка риска до пилота

## Что известно

Только сообщение пользователя: npm audit показывает high в sharp; библиотека используется генератором иконок; предложенный автоматический fix требует мажорного обновления. Точные версия, advisory и цепочка зависимостей не приложены. Автор пакета не подтверждал установленную уязвимую версию.

Нужно различать исходный advisory и сообщение о родительском пакете, который зависит от уязвимого компонента. Не приписывать проекту самую новую CVE из поиска. По состоянию на проверку 17.09.2026 в официальном реестре sharp несколько предупреждений [S3]; одного имени библиотеки недостаточно.

## Что установить без обновления приложения

Прочитать package/lock и call sites. Пользователь получает audit-JSON в том пакете/ workspace, где зависимость установлена. Возможные команды после проверки установленной версии npm:

```text
npm explain sharp
npm audit --json
npm audit --omit=dev --json
```

Это кандидаты для адаптации в USER_RUN, не разрешение агенту запускать сеть. `npm explain` показывает цепочку зависимости [S2]. Audit отправляет перечень зависимостей в настроенный registry; audit с omit имеет более узкую область [S1]. Ненулевой exit audit при найденных уязвимостях может быть ожидаемым результатом диагностики.

Не выполнять `npm audit fix --force`: он может изменить заявленные диапазоны и поставить несовместимые версии [S1]. Фраза «требуется major» из подсказки автоматики ещё не доказывает, что невозможно адресное безопасное решение через родительский пакет, удаление ненужного генератора или проверенное обновление.

## Карточка разбора

| Поле | Что заполнить |
|---|---|
| Пакет и версия | Точное resolved значение и platform-specific/native компоненты, если относятся к advisory |
| Advisory | GHSA/CVE/URL из audit, диапазон, исправленная версия по первоисточнику |
| Цепочка | Прямая/транзитивная; родитель, почему установлена |
| Где исполняется | install/postinstall, сборка, генерация, API, ingestion, работа оператора |
| Какие данные | Только фиксированные доверенные assets либо изображения/URL/вложения внешнего происхождения |
| Достижимый путь | Конкретный call site от входа до затронутого декодера/операции; либо явно не установлен |
| Ограничения | Форматы, источники входа, включённые скрипты, изоляция и секреты окружения |
| Решение | Целевое исправление / отключение конкретного пути / согласованное временное исключение / данных недостаточно |
| Проверка | Что повторить после изменения: generator, lock, builds, canaries, относящиеся unit |
| Остаточный риск | Нельзя обозначать «исправлено», если только ограничили путь |
| Владелец и пересмотр | Кто принял исключение, до какого события/даты, что прекращает его действие |

## Как принимать решение

Если API/парсер/операторский поток подают внешние картинки в уязвимый компонент, такой путь нельзя допускать к пилоту до исправления или реально работающей изоляции/отключения. Не загружать вредоносные образцы ради доказательства на рабочей машине.

Если установлено, что библиотека вызывается исключительно явным генератором на фиксированных доверенных файлах, отсутствует в runtime-пути и не активируется неожиданными lifecycle scripts, это основание для более узкой оценки риска, а не автоматическое снятие high. Владелец может рассмотреть временное исключение для ограниченного действия с зафиксированными условиями. Уязвимость при этом остаётся открытой.

Если первичный advisory относится к installation/build, «не импортируется API» недостаточно. Проверить именно условия указанного advisory, а не только путь обработки изображений. Политика upstream рассматривает недоверенные входы и ограничения обработки отдельно [S3].

Не обязательно блокировать чтение репозитория и все безопасные тесты на синтетике до окончательного решения по источникам. Блокировать нужно конкретные действия, безопасность которых не установлена. Не скрывать issue по признаку «оно было раньше».

## Доказательства

В отчёт передавать версии, advisory, цепочку и обезличенные пути. Не передавать registry credentials, npm tokens, приватные Git URL и `.npmrc` целиком. Источники S1–S4 приведены в [SOURCES.md](SOURCES.md).
