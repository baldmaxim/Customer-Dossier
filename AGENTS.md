# Работа с наш.дом.рф

Если задача касается карточки объекта наш.дом.рф, агент открывает страницу объекта в браузере и читает основной текст отображённой карточки. Прямые HTTP-запросы к API сайта могут отвечать 403; не считайте это отсутствием данных и не подменяйте страницу тестовым `backend/answer.json`.

Раскройте «Все характеристики», затем снимите название, адрес, статус, характеристики, застройщика, генподрядчика, квартиры и основные показатели продаж. Выражение для чтения DOM: `backend/scripts/domrf-browser-capture.js`. Формат результата: `domrf-browser@1`; проверка: `npm run registry:preview -- <файл.json>` в `backend`. При необходимости загрузите его существующей командой `--registry-import`. Подробности — `docs/development/sources/DOMRF_BROWSER_CAPTURE.md`.

Оператор добавляет адреса в админке: «Сбор → Сайты → Карточки ДОМ.РФ». При `DOMRF_BROWSER_ENABLED=true` backend сам читает ожидающие адреса через Playwright. Ручной путь остаётся для диагностики: проверьте ожидающие адреса командой `npm run ingest:once -- --domrf-pending`, откройте страницу в браузере, сохраните снимок и импортируйте его командой `--registry-import`; после успешного импорта очередь сама отмечает снимок полученным. Если в записи задан ID объекта портала, используйте его при привязке.

Раздел «О доме» на сайте помечен как сгенерированный ИИ. Не выдавайте его за первичные сведения. ИНН застройщика в карточке объекта не показан; реквизиты отдельной карточки застройщика требуют отдельной ссылки на источник.
