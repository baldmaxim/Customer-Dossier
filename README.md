# Досье Заказчика

Портал деловой разведки по строительному рынку России. Собирает тексты из Telegram-каналов
и сайтов, структурирует их локальной моделью в LM Studio и отвечает на один вопрос:
**как дела у Заказчика.**

Карточка компании: объекты и роли на них, подрядчики-контрагенты, лента упоминаний
с дословными цитатами, события (срывы сроков, суды, смена подрядчика) и светофор риска.

---

## Что нужно

| | |
|---|---|
| Node.js | 20+ (проверено на 24) |
| PostgreSQL | 14+ (проверено на 18) |
| LM Studio | с загруженной моделью, локальный сервер включён |
| Видеокарта | 8 ГБ VRAM хватает для Qwen3-8B Q4_K_M |

Telegram API (`api_id`/`api_hash`) **не нужен**. Публичные каналы читаются со страницы
`t.me/s/<канал>` обычным GET-запросом, закрытые — пересылкой боту.

## Установка

### 1. База данных

```bash
createdb tg_info
```

### 2. Настройки

```bash
cd backend
cp .env.example .env
```

Заполните в `.env` минимум `DATABASE_URL`. Остальное имеет рабочие значения по умолчанию.

### 3. Схема

```bash
cd backend
npm install
npm run migrate -- --dry   # посмотреть, что применится
npm run migrate
```

Повторный запуск безопасен: применённые миграции пропускаются.

### 4. LM Studio

Загрузите **Qwen3-8B**, квантование **Q4_K_M** (~4.9 ГБ). Настройки:

- контекст **8192**
- Flash Attention — **включить**
- KV cache — **Q8**
- запустить локальный сервер (вкладка Developer → Start Server)

Проверка из проекта:

```bash
npm run pipeline:once -- --check
```

Команда покажет список загруженных моделей и предупредит, если `LMSTUDIO_MODEL`
среди них нет.

> `/no_think` в системном промпте обязателен и уже прописан в коде. Без него Qwen3
> уходит в режим рассуждения, сжигает `max_tokens` и возвращает пустой ответ.

### 5. Источники

**Сначала проверьте, что парсер видит живую вёрстку:**

```bash
npm run ingest:once -- --probe <имя_канала>
```

Команда покажет, сколько узлов нашёл каждый селектор. Если `wrap = 0` при большой
странице — вёрстка `t.me/s/` изменилась, и парсер надо чинить (`TG_SELECTORS`
в [telegramWeb.ts](backend/src/ingest/telegramWeb.ts)) до включения источников.

Затем добавьте каналы:

```bash
npm run ingest:once -- --add имя_канала
npm run ingest:once -- --source имя_канала   # разовый прогон
```

Сайты из сидов заведены со статусом `paused` — включите нужные в админке
после проверки, что парсер видит их вёрстку.

### 6. Форвард-бот (для закрытых каналов)

1. Создайте бота у [@BotFather](https://t.me/BotFather), получите токен.
2. Узнайте свой Telegram user id (например, у [@userinfobot](https://t.me/userinfobot)).
3. Впишите в `.env`: `TG_BOT_TOKEN` и `TG_BOT_ALLOWED_USER_IDS`.

> Пустой `TG_BOT_ALLOWED_USER_IDS` означает **не принимать никого**. Это не оплошность:
> бот, открытый всем, — прямой канал вливания произвольного текста в вашу базу.

Прав администратора в канале боту не нужно — он принимает пересылки в личке.

### 7. Запуск

```bash
cd backend && npm run dev      # API :4100 + ингест + пайплайн + бот
cd frontend && npm install && npm run dev   # :5173
```

## Команды

### Ингест

```bash
npm run ingest:once -- --probe <канал>    # сверить селекторы с живой страницей
npm run ingest:once -- --add <канал>      # добавить публичный канал
npm run ingest:once -- --source <канал>   # прогнать один источник
npm run ingest:once                       # все просроченные источники
npm run ingest:once -- --stats            # документы, очередь, доля дублей
```

### Пайплайн извлечения

```bash
npm run pipeline:once -- --check      # LM Studio поднят? модель загружена?
npm run pipeline:once                 # одна пачка
npm run pipeline:once -- --loop       # пока очередь не опустеет
npm run pipeline:once -- --stats      # очередь и доля неудачных вызовов
npm run pipeline:once -- --merges     # очередь на ручное слияние
npm run pipeline:once -- --merge <id> # подтвердить слияние
npm run pipeline:once -- --reject <id>
```

### Прочее

```bash
npm test                            # 103 теста
npm run migrate                     # миграции
cd frontend && npm run icons:generate   # иконки PWA из одного SVG
```

## Как это устроено

```
источники → raw_documents → extractions → канонический слой → карточка
 t.me/s/     дедуп по        LM Studio     компании, объекты,   светофор
 сайты       нормализ.       + проверка    роли, события        риска
 бот/форма   хэшу            цитат
```

Как пользоваться порталом — [docs/USAGE.md](docs/USAGE.md).
Подробности архитектуры и принятых решений — в [CLAUDE.md](CLAUDE.md),
промпты — в [docs/PROMPTS.md](docs/PROMPTS.md).

### Три вещи, которые стоит знать до правок

**Ничего не попадает в базу без доказательства.** Каждая сущность несёт дословную
цитату, проверенную вхождением в исходный текст, и имя сущности обязано стоять внутри
своей цитаты. Модель на 8B охотно «вспоминает» компании, которых в тексте нет;
подставить выдуманное название в реальный фрагмент она не может.

**Слияние компаний асимметрично.** Слить две компании легко, разлить обратно — почти
невозможно: упоминания, роли и события уже перемешаны. Поэтому в спорных случаях
резолвер создаёт **новую** компанию и кладёт пару в очередь на подтверждение.
Дубль стоит одной кнопки в админке; ошибочное слияние стоит данных.

**Серый светофор — не «всё хорошо».** Компания с менее чем тремя упоминаниями за
90 дней получает статус «мало данных». Без этого любая новая компания с одним
негативным постом мгновенно краснела бы, и порталу перестали бы верить.

## Ограничения

- Читаются только **публичные** Telegram-каналы. Закрытые — вручную через бота.
- Данные собраны из новостей, а не из реестров (ЕГРЮЛ, ЕИСЖС, картотека дел).
  Это повод задать вопросы, а не проверка контрагента.
- Аутентификации нет: MVP рассчитан на локальную сеть. Перед выносом на VPS
  нужен auth-middleware — слияние сущностей необратимо.
- Парсер сайтов (`kind='website'`) ещё не написан: источники заведены, ветка пропускается.
