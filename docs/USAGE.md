# Как пользоваться

Установка — в [README](../README.md). Здесь про повседневную работу.

---

## Что происходит само — и что нет

Запуск `npm run dev` в `backend/` **работает сам**: собирает, разбирает и публикует.
API слушает только `127.0.0.1`. Выключается каждое задание отдельно в `backend/.env`:

| Флаг | Раз в | Что делает |
|---|---|---|
| `INGEST_ENABLED` (по умолчанию `true`) | 1 минуту | проверяет, каким источникам пора, и читает новые посты — **только у источников с подтверждённым допуском к сбору** |
| `PIPELINE_ENABLED` (по умолчанию `true`) | 30 секунд | ставит запуски по новым редакциям и выполняет их моделью |
| `REPROCESS_AUTO_PUBLISH` (по умолчанию `true`) | — | публикует готовый набор кандидатов в карточки. Неполный и упавший запуск не публикуются никогда |
| `METRICS_AUTO_REFRESH` (по умолчанию `true`) | 10 минут | пересчитывает снимок сигналов |
| `BOT_ENABLED` (по умолчанию `false`) | постоянно | принимает форварды боту (нужен допуск `manual:bot` и токен) |
| `MERGE_APPLY_ENABLED` (по умолчанию `false`) | — | применение слияния сущностей: слить легко, разлить почти невозможно |

Включённый `INGEST_ENABLED` сам по себе никуда не ходит: без решения о допуске источник остаётся
на паузе. Что именно опубликовалось и что не прошло — в админке, ступень «Результат».

Вход не требуется: портал открывается сразу, API слушает только loopback и проверяет Host и Origin.

## Первый день: подготовить источники

### 1. Добавить каналы

Через админку (кнопка «Добавить») или командой:

```bash
npm run ingest:once -- --add имя_канала
```

Канал заводится **на паузе** и с допуском «не подтверждён». Только **публичные** каналы:
страница `t.me/s/имя_канала` должна открываться в браузере без входа в Telegram.

Начните с 5–10 каналов. Сотня источников на старте только забьёт очередь и не даст
понять, откуда приходит мусор.

### 1б. Добавить сайт

Админка → «Добавить сайт», либо командой:

```bash
npm run ingest:once -- --add-site erzrf.ru
npm run ingest:once -- --add-site example.ru --rss https://example.ru/news/rss
```

При добавлении запросов к сайту нет. Сайты читаются **через RSS**: лента редко меняет
формат, а дизайн сайта переделывают ежегодно. Адрес ленты портал ищет при первом
разрешённом проходе — в `<head>` страницы и по типовым путям `/rss`, `/feed`, `/atom.xml`.
Ссылки из ленты на чужие домены не открываются.

### 2. Решение о допуске

Админка → «Источники» → «Допуск». Два отдельных решения:

- **Сбор** — можно ли читать источник;
- **ИИ-обработка** — можно ли отдавать его тексты модели.

Для разрешения обязательны основание и ответственный; можно указать срок и ссылку на
решение. Каждое изменение пишется в журнал `source_policy_log`. Причина блокировки
видна прямо в таблице. Статус `active` («опрашивать») без допуска ничего не разрешает.

### 3. Проверить вёрстку и включить

```bash
npm run ingest:once -- --probe имя_канала          # живой запрос: нужен допуск к сбору
npm run ingest:once -- --probe-site erzrf.ru       # то же для сайта
```

`--probe-site` показывает, сколько записей в ленте и как выглядит текст свежей статьи.
Если текст короткий — лента отдаёт только анонс. Затем «Включить» в админке.

Проверить, что идёт:

```bash
npm run ingest:once -- --stats      # сколько документов и что в очереди
npm run pipeline:once -- --stats    # сколько разобрано и сколько ошибок
```

## Проверить Заказчика

Главный сценарий. Вводите название в **любом написании** — «ПИК», «ГК ПИК»
и «PIK» найдут одну и ту же компанию — или ИНН/ОГРН.

На карточке сверху — вердикт словами и **устаревший индекс сигналов** (помечен legacy):

| | |
|---|---|
| **Мало данных** | упоминаний меньше трёх. Портал молчит, судите обычным порядком |
| **Сигналов не найдено** | в собранных публикациях сигналов нет — это **не** «проблем нет» |
| **Есть сигналы** | упоминались срывы сроков или негативный фон |
| **Много сигналов** | упоминались суды, банкротство, отзыв лицензии или системные срывы |

Индекс эвристический и некалиброванный: суд засчитывается без роли стороны, событие
без даты — как свежее, задержка объекта — всем текущим участникам. Не основание для
решения о сотрудничестве. Замена объяснимыми сигналами — этап 07.

Дальше — метрики, объекты с ролями и контрагентами, события, лента упоминаний.

**Каждое утверждение можно проверить.** У упоминания есть дословная цитата и ссылка
«оригинал» на исходный пост. Цитата подтверждает, что так написано, а не что это правда.
Пометка **«цитата не сверена»** — модель пересказала, а не процитировала.

## Очередь слияний

Резолвер намеренно осторожен. Когда он не уверен, «Стройинвест» и «Строй-Инвест» —
одна компания или две, он **создаёт вторую** и кладёт пару в очередь. Точное совпадение
названия тоже не склеивает компании, если реквизиты или организационная форма расходятся,
а одноимённых кандидатов несколько. Одноимённые ЖК без известного города не склеиваются.

**Слияние сейчас выключено** (кнопка неактивна, CLI `--merge` отказывает): в нём нет
проверки реквизитов, блокировок и отката. Безопасная версия — этап 04. Отклонить неверную
пару кнопкой «Разные» можно — она больше не всплывёт.

## Проверить качество карточек

```bash
npm run pipeline:once -- --audit
```

Четыре раздела:
1. **Скрытые дубли** — похожие компании, по которым нет решения в очереди слияний.
2. **Роли** — сколько упоминаний с каждой ролью. Если проектировщиков больше,
   чем генподрядчиков и подрядчиков вместе, команда предупредит: в стройновостях так
   не бывает, значит, аналитиков и консультантов записывают проектировщиками.
3. **Объекты, записанные компаниями** — компании с тем же названием, что у объекта.
4. **Выборка для проверки глазами** — «компания → роль → цитата».

**Дубль с совпадающим ключом** почти всегда означает устаревшую нормализацию:
название записали старыми правилами. Посмотреть, что изменил бы пересчёт:

```bash
npm run pipeline:once -- --renormalize --dry
```

Запись ключей в рабочую базу выключена до версионного пересчёта на копии (этап 04).

**После правки промпта** не переразбирайте базу: переразбор любого объёма (одного
документа или всей базы) удаляет прежние роли и события документа, в том числе
подтверждённые другими источниками. Команды `--reextract`, `--retry`, `--loop`
заблокированы до этапа 03B. Качество нового промпта проверяйте теневым прогоном —
он пишет только в `extractions` (см. «Выбрать модель» ниже).

## Удалить источник

Кнопка «Удалить» в таблице источников удаляет источник, **только если по нему нет
документов**. Если документы есть — поставьте источник на паузу или отзовите допуск:
сбор останавливается, собранное и его прослеживаемость остаются. Удаление вместе с
документами выключено: оно унесло бы упоминания и события, а роли на объектах
остались бы без доказательств.

## Закрытые каналы и разовые тексты

**Форвард боту.** Пересылаете интересный пост своему боту в личку — он отвечает
«Принято» и сохраняет текст. Нужны `BOT_ENABLED=true` и допуск источника
«Форварды в Telegram-бота». Прав администратора боту не нужно.

**Вставка текста.** Админка → «Вставить текст вручную». Нужен допуск источника
«Ручная вставка текста» — без него текст не сохраняется, причина видна в сообщении.

## Когда что-то сломалось

**Красный баннер в админке «Сломаны источники».** Две обычные причины: канал стал
закрытым или изменилась вёрстка `t.me/s/`. Проверить (нужен допуск к сбору):

```bash
npm run ingest:once -- --probe имя_канала
```

Команда покажет, сколько узлов нашёл каждый селектор. `wrap = 0` при большой странице —
вёрстка поменялась, парсер нужно чинить. Починив источник, включите его в админке
(кнопка «Включить» сбрасывает счётчик неудач).

**Модель не отвечает.**

```bash
npm run pipeline:once -- --check
```

**В карточке висит явно неверный город или адрес.** Скорее всего, значение записано
старой версией кода. Посмотреть, что не подтверждается исходными текстами:

```bash
npm run pipeline:once -- --recheck --dry
```

Снятие полей в рабочей базе выключено вместе с остальными массовыми правками канона.

**Выбрать модель: какая лучше — 8B или 4B?** Не на глаз, а на одних и тех же
документах. Разборы разных моделей хранятся рядом и карточки не меняют. Теневой
прогон берёт только документы источников с допуском к ИИ-обработке:

```bash
# в .env: LMSTUDIO_MODEL=qwen3-8b
npm run pipeline:once -- --shadow 30 --source stroygaz.ru
# в .env: LMSTUDIO_MODEL=qwen3-4b-instruct-2507
npm run pipeline:once -- --shadow 30 --source stroygaz.ru
npm run pipeline:once -- --compare
```

`--compare` покажет по каждой модели долю успешных разборов, долю признанных
релевантными, среднее и максимальное время — и главное, **список документов,
где модели разошлись**. Откройте несколько через `--doc <id>`: там и ответ.

Про таймауты 8B: сначала проверьте контекст в LM Studio. Кэш на 16K токенов
вместе с весами 8B не помещается в 8 ГБ, модель уезжает в оперативную память
и замедляется в разы. При `EXTRACT_CHUNK_SIZE=3500` контекста 8192 хватает
с запасом. Текст длиннее `EXTRACT_CHUNK_SIZE × EXTRACT_MAX_CHUNKS` (с учётом
перекрытия) не разбирается частично, а помечается ошибкой `incomplete`.

**Модель слишком часто говорит «нерелевантно».**

```bash
npm run pipeline:once -- --skipped
npm run pipeline:once -- --skipped --source stroygaz.ru
```

Первым делом команда покажет долю нерелевантного по источникам. Высокая доля
у отраслевого издания, которое целиком про стройку, — повод подозревать модель,
а не источник.

**Много ошибок разбора.** `npm run pipeline:once -- --stats` покажет долю неудачных
вызовов и их причины, `--errors` — тексты ошибок.

## Чему портал не замена

- Данные собраны **из новостей**, а не из реестров. Это повод задать вопросы
  контрагенту, а не заключение о его надёжности.
- «Мало данных» и «сигналов не найдено» ≠ «всё хорошо». Отсутствие в выборке не
  означает отсутствия в жизни.
- Тональность ставит языковая модель. Один резкий пост не делает компанию плохой —
  поэтому в индексе и заложен порог в три упоминания.
- Роли (заказчик / генподрядчик / подрядчик) извлекаются из текста новостей.
  Слово «застройщик» покрывает все три — в спорных случаях модель обязана
  ставить «неизвестно», но ошибается и она.
