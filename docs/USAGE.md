# Как пользоваться

Установка — в [README](../README.md). Здесь про повседневную работу.

---

## Что происходит само

Когда запущен `npm run dev` в `backend/`, портал работает без вашего участия:

| Раз в | Что делает |
|---|---|
| 1 минуту | проверяет, каким источникам пора, и читает новые посты |
| 15 минут | опрашивает каждый канал (интервал меняется в админке) |
| 30 секунд | берёт из очереди до 8 документов и отдаёт их модели |
| 10 минут | пересчитывает метрики и светофоры |

Вручную ничего запускать не нужно. CLI-команды из README — для отладки и разовых прогонов.

## Первый день: наполнить базу

### 1. Добавить каналы

Через админку (кнопка «Добавить») или командой:

```bash
npm run ingest:once -- --add имя_канала
```

Только **публичные** каналы: страница `t.me/s/имя_канала` должна открываться в браузере
без входа в Telegram. Если просит открыть в приложении — канал закрытый.

Начните с 5–10 каналов. Сотня источников на старте только забьёт очередь и не даст
понять, откуда приходит мусор.

### 1б. Добавить сайт

Админка → «Добавить сайт», либо командой:

```bash
npm run ingest:once -- --probe-site erzrf.ru   # сначала проверить
npm run ingest:once -- --add-site erzrf.ru     # потом добавить
```

Сайты читаются **через RSS**, а не разбором вёрстки: лента редко меняет формат,
а дизайн сайта переделывают ежегодно. Адрес ленты портал ищет сам — в `<head>`
страницы и по типовым путям `/rss`, `/feed`, `/atom.xml`. Не нашёл — укажите
вручную:

```bash
npm run ingest:once -- --add-site example.ru --rss https://example.ru/news/rss
```

`--probe-site` показывает, сколько записей в ленте и как выглядит текст свежей
статьи. Если текст короткий — лента отдаёт только анонс, и стоит задать
`articleSelector` в настройках источника.

### 2. Подождать

Первый проход соберёт свежие посты с каждого канала (одну страницу, это примерно
20 последних сообщений). Дальше портал добирает только новое.

Проверить, что идёт:

```bash
npm run ingest:once -- --stats      # сколько документов и что в очереди
npm run pipeline:once -- --stats    # сколько разобрано и сколько ошибок
```

### 3. Разобрать очередь слияний

Это главное, что портал **не может** сделать за вас. См. раздел ниже.

## Проверить Заказчика

Главный сценарий. Вводите название в **любом написании** — «ПИК», «ГК ПИК»
и «PIK» найдут одну и ту же компанию.

На карточке сверху — вердикт словами и светофор:

| | |
|---|---|
| **Мало данных** | упоминаний меньше трёх. Портал молчит, судите обычным порядком |
| **Без замечаний** | проблем в открытых источниках не нашлось |
| **Есть вопросы** | есть срывы сроков или негативный фон |
| **Высокий риск** | суды, банкротство, отзыв лицензии или системные срывы |

Дальше — метрики, объекты с ролями и контрагентами, события, лента упоминаний.

**Каждое утверждение можно проверить.** У упоминания есть дословная цитата и ссылка
«оригинал» на исходный пост. Если рядом с цитатой стоит пометка **«цитата не сверена»** —
модель пересказала, а не процитировала, и такой факт требует проверки руками.

## Ежедневная работа: очередь слияний

**Единственная задача, которая требует человека.** Пять минут в день.

Резолвер намеренно осторожен. Когда он не уверен, «Стройинвест» и «Строй-Инвест» —
одна компания или две, он **создаёт вторую** и кладёт пару в очередь. Причина простая:
склеить два дубля — одна кнопка, а разлить ошибочно слитые компании почти невозможно,
упоминания и роли уже перемешаны.

Цена этого решения — если очередь не разбирать, база наполняется дублями и метрики
занижаются: половина объектов у одной карточки, половина у другой.

Админка → «Очередь слияний». По каждой паре два варианта: **«Это одна компания»**
или **«Разные»**. Оба решения окончательные — отклонённая пара больше не всплывёт.

Признак, что вы запустили очередь: на главной появится предупреждение о компаниях
ровно с одним упоминанием.

## Удалить источник

Кнопка «Удалить» в таблице источников. Если по источнику ещё нет документов,
он удалится сразу. Если документы есть — портал спросит подтверждение.

**Подумайте, точно ли нужно удаление.** Каждое утверждение в карточке
прослеживается до источника; удалив источник вместе с документами, вы уносите
и извлечённые из них упоминания с событиями. Обычно нужнее **пауза**: сбор
останавливается, собранное остаётся.

Удаление вместе с документами оправдано, когда добавили не тот канал и он
натаскал мусора. Компании и объекты при этом остаются — они могли упоминаться
и в других источниках; осиротевшие поля подчистит `--recheck`.

## Закрытые каналы и разовые тексты

**Форвард боту.** Пересылаете интересный пост своему боту в личку — он отвечает
«Принято» и ставит текст в очередь. Работает для любых каналов, включая закрытые.
Прав администратора боту не нужно.

**Вставка текста.** Админка → «Вставить текст вручную». Для статей, выжимок из PDF
и всего, до чего парсер не дотягивается. Текст пойдёт тем же путём, что и остальное.

## Когда что-то сломалось

**Красный баннер в админке «Сломаны источники».** Две обычные причины: канал стал
закрытым или изменилась вёрстка `t.me/s/`. Проверить:

```bash
npm run ingest:once -- --probe имя_канала
```

Команда покажет, сколько узлов нашёл каждый селектор. `wrap = 0` при большой странице —
вёрстка поменялась, парсер нужно чинить. Починив источник, включите его в админке
(кнопка «Включить» сбрасывает счётчик неудач).

**Очередь растёт, ничего не разбирается.** Проверьте модель:

```bash
npm run pipeline:once -- --check
```

**В карточке висит явно неверный город или адрес.** Скорее всего, значение
записано старой версией кода, а переизвлечение его не снимает: новый разбор
просто молчит про это поле, а молчание — не опровержение. Перепроверить всё
разом против исходных текстов:

```bash
npm run pipeline:once -- --recheck --dry   # показать, что не подтверждается
npm run pipeline:once -- --recheck         # снять неподтверждённое
```

**Выбрать модель: какая лучше — 8B или 4B?** Не на глаз, а на одних и тех же
документах. Разборы разных моделей хранятся рядом и карточки не меняют:

```bash
# в .env: LMSTUDIO_MODEL=qwen3-8b
npm run pipeline:once -- --shadow 30 --source stroygaz.ru
# в .env: LMSTUDIO_MODEL=qwen3-4b-instruct-2507
npm run pipeline:once -- --shadow 30 --source stroygaz.ru
npm run pipeline:once -- --compare
```

`--compare` покажет по каждой модели долю успешных разборов, долю признанных
релевантными, среднее и максимальное время — и главное, **список документов,
где модели разошлись**. Откройте несколько через `--doc <id>`: там и ответ.

Про таймауты 8B: сначала проверьте контекст в LM Studio. Кэш на 16K токенов
вместе с весами 8B не помещается в 8 ГБ, модель уезжает в оперативную память
и замедляется в разы. При `EXTRACT_CHUNK_SIZE=3500` контекста 8192 хватает
с запасом.

**Модель слишком часто говорит «нерелевантно».**

```bash
npm run pipeline:once -- --skipped
npm run pipeline:once -- --skipped --source stroygaz.ru
```

Первым делом команда покажет долю нерелевантного по источникам. Высокая доля
у отраслевого издания, которое целиком про стройку, — повод подозревать модель,
а не источник.

**Много ошибок разбора.** `npm run pipeline:once -- --stats` покажет долю неудачных
вызовов и их причины. Больше 2 % — повод смотреть промпт. Если правите промпт,
обязательно поднимите `PROMPT_VERSION` в `.env`, иначе старые документы не переизвлекутся.

## Чему портал не замена

- Данные собраны **из новостей**, а не из реестров. Это повод задать вопросы
  контрагенту, а не заключение о его надёжности.
- «Мало данных» ≠ «всё хорошо». Это означает ровно то, что написано.
- Тональность ставит языковая модель. Один резкий пост не делает компанию плохой —
  поэтому в светофоре и заложен порог в три упоминания.
- Роли (заказчик / генподрядчик / подрядчик) извлекаются из текста новостей.
  Слово «застройщик» покрывает все три — в спорных случаях модель обязана
  ставить «неизвестно», но ошибается и она.
