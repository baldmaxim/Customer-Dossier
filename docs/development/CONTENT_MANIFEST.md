# Контракт content-manifest@1 — доказательство восстановления по содержимому

Дата: 2026-09-16. Появился при закрытии приёмки этапа 09 (замечания F02, R06/R07 пакета 10–19).
Код: `backend/src/release/manifestSpec.ts` (перечень), `manifest.ts` (формат, сериализация, сравнение),
`manifestCollect.ts` (чтение базы), `manifestCli.ts` (команда). Тесты: `release/manifest.test.ts` (unit),
`release/manifest.int.test.ts` (PostgreSQL, запускает пользователь).

## Зачем

`release:check` (`local-inventory@2`) сравнивает количества, состояние источников, число решений и снимков.
Совпадение количеств не доказывает, что совпали тексты редакций, цитаты, реквизиты, решения аналитика и payload
снимков. Manifest хеширует фактическое содержимое каждой строки. Быстрый inventory сохранён и остаётся первой
проверкой; manifest — содержательная. Ни один из них не заменяет чтение восстановленной копии через приложение.

## Команды

```powershell
cd backend
npm run release:manifest -- --out before-manifest.json       # снять (только чтение, DATABASE_URL)
npm run release:manifest -- --compare before-manifest.json   # сравнить текущую базу с сохранённым
```

Exit 0 — только `MATCH` (при `--compare`) или manifest без проблем (без `--compare`). Иначе exit 1.

## Перечень

Все 42 таблицы схемы public (41 из миграций 001–020 + `schema_migrations`) перечислены в `TABLE_SPECS` с классом
и причиной: `domain` (источники, публикации, редакции, утверждения, доказательства, решения, компании, реквизиты,
объекты, обращения, снимки), `history` (журналы допуска, публикаций, слияний и перенос строк, вымарывания, версии
обращений, бот), `pipeline` (запуски, чанки, ответы, наборы кандидатов), `operational` (проходы сбора, `http_cache`,
`backfill_checkpoints`), `registry` (`schema_migrations`). Unit-тест сверяет перечень со всеми `CREATE TABLE` миграций.

- Таблица в базе, которой нет в перечне → `UNCLASSIFIED_TABLE` (новая миграция обязана дополнить перечень).
- Таблица из перечня, которой нет в базе → `MISSING_TABLE` (это не то же, что пустая таблица).
- Исключение колонки — только с причиной в `excludedColumns`. **Сейчас исключений нет**: генерируемые колонки
  (`ts`, `name_key`) тоже хешируются.

Сознательно не хешируются как строки (`NOT_FINGERPRINTED`, пишется в каждый manifest):

| Объект | Почему |
|---|---|
| представления `*_v`, `company_risk` | производные от таблиц; определение входит в раздел схемы `views` |
| материализованное `company_metrics` | legacy-производная; определение в схеме, данные пересчитываются |
| OID, физическое размещение, статистика | не доменные данные, законно различаются после restore |
| `COMMENT ON DATABASE` (маркер тестовой цели) | свойство базы; `pg_dump` без `--create` его не переносит — маркер ставится на restore-цель вручную |
| роли кластера, пароли, конфигурация сервера | вне дампа одной базы |
| секреты окружения (`.env`, токен оператора) | не публикуются и не хешируются |

Таблиц сессий, паролей и токенов в базе нет: сессии оператора — в памяти процесса (`api/auth.ts`), токен —
`backend/.local/operator-token` или `OPERATOR_TOKEN`. Их сохранность вне дампа и проверяется отдельно (п. «Окружение»).

## Чтение

- Одна транзакция `REPEATABLE READ READ ONLY`: все разделы относятся к одной точке данных, запись невозможна.
- Параметры сессии фиксированы: `TimeZone=UTC`, `DateStyle=ISO, YMD`, `IntervalStyle=postgres`,
  `extra_float_digits=3`, `bytea_output=hex`.
- Каждая колонка читается как `::text` в режиме массива строк: JS-парсеры pg (int8 → Number, numeric → float,
  date) не участвуют, точность не теряется.
- Строки — серверным курсором `DECLARE … NO SCROLL CURSOR … ORDER BY <первичный ключ>` (составной ключ — все его
  колонки; без ключа — все колонки), `FETCH 1000`. Пагинации OFFSET нет, пропуска строк быть не может.

## Сериализация `pg-text-row@1`

- Колонки упорядочены по имени; `columnsHash = sha256(JSON [[имя, format_type], …])`.
- Строка: `sha256(JSON.stringify([значение::text | null, …]))`. `NULL` ≠ `''`; Unicode не нормализуется
  (NFC и NFD — разные цитаты); `jsonb::text` — каноническая форма PostgreSQL; границы колонок сохраняются.
- Таблица: `sha256(columnsHash + число строк + отсортированные дайджесты строк)` — не зависит от порядка выборки.
- Хранимым хешам (`payload_hash`, `content_key`, `evidence_set_hash`) не доверяем: они сами входят в строку, а hash
  снимка дополнительно пересчитывается.

## Разделы

| Раздел | Что | Проблема (exit 1) |
|---|---|---|
| `tables` | fingerprint каждой таблицы перечня | `UNCLASSIFIED_TABLE`, `MISSING_TABLE` |
| `schema` | хеши: колонки (тип, NOT NULL, default, generated, identity), ограничения (`pg_get_constraintdef`), индексы, триггеры, функции public (кроме функций расширений), представления, enum-метки, расширения с версиями | при сравнении `SCHEMA_DIFFERS` |
| `migrations` | число и хеш применённых файлов; сверка с `docs/migrations` текущего кода | `REGISTRY_MISSING`, `PENDING_MIGRATION`, `UNKNOWN_MIGRATION` |
| `sequences` | `pg_sequences.last_value` каждой последовательности и `max(id)` её таблицы; `nextval`/`setval` не вызываются | `SEQUENCE_BEHIND_DATA` (следующая вставка упадёт) |
| `snapshots` | пересчёт `payloadHash(payload)` по `sha256-canonical-json@1`; цепочка вымарываний (каждое `hash_before` = предыдущее `hash_after`, последнее = текущий hash) | `SNAPSHOT_HASH_MISMATCH`, `SNAPSHOT_UNKNOWN_ALGORITHM`, `REDACTION_CHAIN_BROKEN` |
| `integrity` | 10 проверок связности `local-inventory` | `INTEGRITY_VIOLATION`, `INTEGRITY_SKIPPED` (пропуск — не PASS) |
| `config` | не-секретные параметры процесса, снимавшего manifest (`CONFIG_KEYS`) | при сравнении `CONFIG_MISMATCH`; `BACKGROUND_ENABLED`, если фоновое задание включено при проверке восстановления |
| `meta` | время, имя базы, маркер, Node | **не сравнивается** |

## Окружение (config manifest)

Дамп базы не переносит `.env`: флаги берутся из окружения процесса. В manifest пишутся только значения
`CONFIG_KEYS` (фоновые флаги, `REVISION_WRITE_ENABLED`, `GRAPH_EXPORT_ENABLED`, `MERGE_APPLY_ENABLED`,
`REPROCESS_AUTO_PUBLISH`, `EXTRACT_SCHEMA_VERSION`, `PROMPT_VERSION`, `LMSTUDIO_MODEL`, `EXTRACT_CHUNK_*`,
`EXTRACT_CONCURRENCY`, `HOST`, `PORT`, `SESSION_*`). `CONFIG_DENYLIST` (`DATABASE_URL`, `TEST_DATABASE_URL`,
`OPERATOR_TOKEN`, `TG_BOT_TOKEN`, `TG_BOT_ALLOWED_USER_IDS`, `LMSTUDIO_BASE_URL`, `DATABASE_SSL_CA_PATH`) не пишется
ни значением, ни хешем. Наличие токена оператора и `.env` на машине восстановления проверяет пользователь
вручную (вход в приложение), без выгрузки значений.

## Сравнение и вердикты

| Вердикт | Когда |
|---|---|
| `MATCH` | формат совпал, все разделы есть, проблем нет, содержимое/схема/миграции/последовательности/число снимков/параметры равны |
| `MISMATCH` | любое расхождение или проблема одной из сторон; печатаются раздел, код и объект (без значений) |
| `INCOMPLETE` | в одном из файлов нет обязательного раздела |
| `INCOMPATIBLE` | другая версия формата или сериализации (в т. ч. файл `local-inventory` вместо manifest) — снимите заново |

Имя restore-базы, время съёмки и машина — метаданные и расхождением не являются. Даты источников и решений,
id доказательств и содержимое снимков — данные и сравниваются.

## Когда сравнение осмысленно

Baseline, дамп и сравнение должны относиться к одной точке данных: писатели остановлены (API, сбор, конвейер, бот,
пересчёт, замеры, ручные снимки), активных запусков нет. `pg_dump` делает согласованный снимок сам, но manifest,
снятый отдельной командой, может относиться к другому моменту — поэтому после дампа manifest источника снимается
повторно и сравнивается с baseline («источник не менялся во время дампа»). Порядок — `evidence/09/USER_RUN_CLOSURE.md`, раздел E.

## Что manifest не доказывает

- Что приложение читает восстановленную копию: это отдельная проверка (вход, досье, снимок, выгрузки, `release:probe`).
- Что роли кластера, `.env` и токен перенесены: вне дампа.
- Истинность сведений: хеш подтверждает совпадение байтов, а не содержание публикаций.

## Совместимость и откат

Новых миграций нет. Формат версионирован: изменение перечня или сериализации — новая версия, старый файл даёт
`INCOMPATIBLE`, а не ложный `MATCH`. `local-inventory@1` (файлы прогона 09) сравнивается с `@2` как несовместимый.
Откат — не использовать `release:manifest`; модуль ничего не запускает сам и в базу не пишет.
