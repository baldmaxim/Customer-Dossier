# LOCAL_RUNBOOK — локальная эксплуатация портала

Для одного оператора на одной машине (Windows 10/11, PowerShell 5.1 + Git Bash; на Linux/macOS те же команды
с `export` вместо `$env:`). Портал слушает только `127.0.0.1`. Облака, публичного адреса и второго пользователя
здесь нет и не предполагается.

Проверено на: Windows 10 Pro 19045, Node v24.13–24.14, npm 11.11, PostgreSQL 17/18 в Docker (тестовая цель).
Команды ниже выполняются из корня `TG_Info`.

---

## 1. Что где лежит

| Что | Где | В резервную копию |
|---|---|---|
| Код | репозиторий `TG_Info` | Git |
| Схема БД | `docs/migrations/NNN_*.sql` | Git |
| Данные (публикации, редакции, утверждения, решения, обращения, снимки) | PostgreSQL, база портала | **да**, дамп БД |
| Настройки и секреты | `backend/.env` (создаёт пользователь) | да, но **отдельно** и не в Git |
| Токен оператора | `backend/.local/operator-token` (или `OPERATOR_TOKEN` в `.env`) | да, отдельно |
| Сборка интерфейса | `frontend/dist` | нет, пересобирается |
| Логи | вывод в консоль; файлового журнала нет | нет |
| Вложения и файлы источников | не хранятся: портал держит тексты в БД, файлов на диске не создаёт | — |

Соответствие «запись ↔ файл» восстанавливать не нужно: внешних blob-файлов нет. Если они появятся, в резервную
копию обязаны попасть и файлы, и строки, ссылающиеся на них, одним снимком.

---

## 2. Запуск и остановка

```powershell
# Переменные текущего окна: база, отключение внешнего .env для проверочных прогонов
$env:DATABASE_URL = 'postgresql://<пользователь>:<пароль>@127.0.0.1:5432/<база>'
$env:DATABASE_SSL = 'false'

cd backend
npm ci                  # первый раз и после git pull с изменением package-lock.json
npm run migrate -- --dry   # план миграций: что будет применено
npm run migrate            # применить (009 — только с --allow-destructive и после backup)
npm run dev                # API на 127.0.0.1:4100
```

```powershell
cd frontend
npm ci
npm run dev             # интерфейс на 127.0.0.1:5173, /api проксируется на 4100
```

Остановка — `Ctrl+C` в обоих окнах. Фоновых служб портал не ставит: после `Ctrl+C` ничего не остаётся.

**Старт портала сам по себе ничего не собирает.** Сбор, разбор моделью, пересчёт сигналов и бот включаются
только флагами в `.env` (`INGEST_ENABLED`, `PIPELINE_ENABLED`, `METRICS_AUTO_REFRESH`, `BOT_ENABLED`) — по
умолчанию все выключены, и при старте в консоли печатается, что именно выключено.

Вход: токен из `backend/.local/operator-token` вводится на экране входа. Токен не печатается в логах, не
хранится в localStorage и не попадает в выгрузки.

## 3. Первый пользовательский сценарий

1. Открыть `http://127.0.0.1:5173`, войти токеном оператора.
2. **Поиск** — ввести название компании. Одноимённые юрлица показаны отдельными строками с реквизитами;
   выбирается нужное по ИНН/ОГРН, а не первое совпавшее.
3. **Карточка компании** — резюме с атрибуцией («в публикации сообщается» / «проверено аналитиком»),
   объяснимые сигналы (у каждого числа — правило, окно и исходные записи), контрагенты, противоречия,
   ограничения выборки. Итоговой оценки надёжности нет.
4. **Создать обращение** — объект, корпус, вид работ, заявленная роль и заказчик со слов, условия. Это запись
   оператора: в утверждения и доказательства она не превращается.
5. **Досье обращения** — что установлено источниками, что только заявлено, кто заказывает работы, контекст
   объекта, что не установлено, вопросы контрагенту. Каждая фраза открывает своё утверждение с цитатой и
   редакцией публикации.
6. **Схема связей** — цепочка «заказчик → генподрядчик → подрядчик» с фильтрами по корпусу, периоду и типу
   связи; путь через третью компанию не означает прямого договора.
7. **Проверка** — разобрать противоречие: две версии рядом, решение с обязательной причиной.
8. **Снимок досье** — «Создать снимок», затем «Версия для печати» / «Скачать Markdown» / «Скачать JSON».
   Снимок дальше не меняется: новая публикация, слияние и переименование на него не влияют.

## 4. Сбор источников (только при подтверждённом допуске)

```powershell
cd backend
npm run ingest:once -- --stats            # что уже собрано, очередь, доля дублей
npm run ingest:once -- --add <канал>      # добавить канал: заводится на паузе, без допуска
# допуск на сбор и на ИИ-обработку ставит оператор в админке, с основанием
npm run ingest:once -- --probe <канал>    # живой запрос: только после допуска
npm run pipeline:once -- --check          # доступна ли локальная модель
npm run pipeline:once -- --reextract --limit 20 --source <ключ>
npm run pipeline:once                     # выполнить поставленные запуски
npm run pipeline:once -- --runs           # покрытие и наборы кандидатов
npm run pipeline:once -- --publish <набор>
npm run metrics:refresh                   # снимок сигналов на срез
```

**Остановить сбор:** `Ctrl+C` в окне `npm run dev`; снять `INGEST_ENABLED`/`PIPELINE_ENABLED` в `.env`;
для отдельного источника — поставить его на паузу в админке. Очередь не теряется: запуски и курсоры лежат
в базе (`extraction_runs`, `sources.cursor`). **Курсоры и журнал бота не обнулять** — это не «сброс кэша»,
а потеря отметки о прочитанном.

Проверить очередь: `npm run pipeline:once -- --runs` и `--errors`; допуск и здоровье источников — админка.

## 5. Резервная копия и восстановление

Копируется вся база одним дампом — иначе редакции, доказательства и решения аналитика разъедутся между собой.

```powershell
# Копия (тестовая база в Docker; для установки без Docker — тот же pg_dump локально)
docker exec tg-info-test-db pg_dump -U tg_test -Fc -d tg_info_test > backup-tg-info-YYYYMMDD.dump

# Контрольные числа ДО копии
cd backend
npm run release:check -- --out before.json
```

Восстановление — **только в отдельную, явно другую цель**, не поверх рабочей:

```powershell
docker exec tg-info-test-db psql -U tg_test -d postgres -c "CREATE DATABASE tg_info_test_restore;"
docker exec -i tg-info-test-db pg_restore -U tg_test -d tg_info_test_restore --no-owner < backup-tg-info-YYYYMMDD.dump

$env:DATABASE_URL = 'postgresql://tg_test:tg_test@127.0.0.1:55433/tg_info_test_restore'
npm run release:check -- --compare before.json
```

Ожидается «совпадает с before.json». Расхождения печатаются построчно: таблица, источник, решения, снимки,
нарушения связности. Дамп — бинарный файл: в Git и в переписку не кладётся, хранится рядом с `.env`-секретами.

Что входит в копию: все таблицы, включая `document_revisions` (неизменяемые редакции), `evidence`,
`review_decisions` (решения аналитика), `dossier_cases` и `dossier_case_versions`, `dossier_snapshots`
с вымарываниями, состояние допуска источников и курсоры. Флаги в копию не входят — они в `.env`.

**Хранение и очистка.** Автоматической очистки нет. Редакции, доказательства и решения не удаляются по замыслу:
на них ссылаются цитаты в досье и снимках. Безопасный ручной порядок, если места не хватает:

1. Сделать копию и проверить восстановление (см. выше).
2. Удалять **только** заведомо синтетические данные: `sources.is_synthetic = true` вместе с их публикациями —
   и только на тестовой цели.
3. Снимки досье удалять нельзя (запрещено триггером). Если снимок больше не нужен по правовым основаниям —
   вымарывание фрагмента, а не удаление строки.
4. Логи файлами не пишутся; чистить нечего.

Обещания «хранится вечно» здесь нет: это локальная машина, и сохранность данных равна сохранности диска
и регулярности копий.

**Нехватка места.** Запись публикации и продвижение курсора идут одной транзакцией: при ошибке записи
курсор не двигается, и страница будет прочитана заново. Если диск закончился, PostgreSQL вернёт ошибку —
в интерфейсе это видно как ошибка, а не как «новостей нет». Освободить место и повторить запуск.

## 6. Проверка установки

```powershell
cd backend
npm run release:check                  # контрольные числа, связность, источники, флаги
npm run release:bench                  # фактические времена (только тестовая база: создаёт снимок)
npm test                               # unit, без БД и сети
$env:TEST_DATABASE_URL = 'postgresql://tg_test:tg_test@127.0.0.1:55433/tg_info_test'
npm run test:integration               # только размеченная тестовая база
```

`npm run release:check` ничего не пишет. `release:bench` создаёт снимки досье, поэтому отказывает на базе,
в имени которой нет `test`.

## 7. Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `Нет соединения с БД` при старте | проверить, что PostgreSQL запущен и `DATABASE_URL` указывает на него; портал сознательно не стартует «наполовину» |
| Экран входа вместо данных | сессия истекла — войти заново; данные прежней сессии офлайн не читаются (`/api` не кэшируется) |
| «Схема и выгрузки отключены» | снят флаг `GRAPH_EXPORT_ENABLED` — вернуть или оставить как откат этапа 08B |
| Разбор не ставится: `refused_policy` | у источника нет допуска на ИИ-обработку — решение оператора в админке, с основанием |
| Модель недоступна | портал работает на накопленных данных; новые тексты не разбираются, ошибка видна в `--errors` |
| Белый экран после обновления | обновить страницу (service worker предлагает новую версию явно); кэш `/api` не используется |
| Миграция упала | она откатилась целиком; починить SQL и повторить — применённые файлы не переписываются |
