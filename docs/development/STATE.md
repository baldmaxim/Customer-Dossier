### Задача владельца 21.09.2026 — портал просматривает, а не публикует

Пять правок по замечаниям владельца, одним заходом (не этап пакета):

1. **Обработка без оператора.** Из интерфейса убраны «Поставить на разбор», «Повторить», «Отменить»,
   «Опубликовать этот набор»; `/admin/process` и карточка запуска — только чтение, панель набора —
   `CandidateSetPanel`. Серверные маршруты, `publish.ts` и CLI не тронуты. Слово «публикация» как действие
   с экранов убрано.
2. **Строки кликаются целиком** — каталог компаний и лента «Последнее» (`.row-link` в `src/index.css`,
   проверка перехода по пустой ячейке — в `e2e/dailyRoute.spec.ts`).
3. **Карточка компании: `signals@2`** — договоры, корпоративные связи, контрагенты, пакеты работ, события
   по видам, число судебных дел, края выборки по датам. Панель показателей вынесена во всю ширину, плитки
   больше не рвут подписи. Старые снимки остаются `signals@1`: числа появятся после `metrics:refresh`.
4. **Тема публикации моделью (headline@1)** — миграция `027_revision_headlines.sql`, `llm/headline/*`,
   `headline/service.ts`, `npm run pipeline:once -- --headlines`, флаги `HEADLINE_*`. Тема помечена как
   машинная, доказательством не является.
5. **Страница документа** отвечает «что портал взял из этого текста»: `GET /api/items/:id/extraction`,
   состояние словами, утверждения с цитатами и ссылками на карточки, текст и версии — ниже.

Следом, по тем же скринам: схема связей больше не печатает пояснения дважды (`graph.notes` дублировались
внизу панели) и не занимает пол-карточки — фильтры свёрнуты там, где схема боковая панель; строки
«Подрядчиков» и мобильные карточки кликаются целиком, как в каталоге. Новый эндпоинт
`/api/items/:id/extraction` покрыт интеграционно в `reprocess.int.test.ts` (состояние, цитаты дословно
из редакции, 404 на неизвестную публикацию).

Офлайн-проверки: backend typecheck 0, `npm test` 640+4 новых файла; frontend typecheck 0, `npm test` 34,
`check:labels` ok, `build` + `check:build` ok. Полный прогон vitest на фронте на этой машине требует
`--maxWorkers=1`: при свободных ~1 ГБ ОЗУ параллельные воркеры падают по памяти (к коду отношения не имеет).
