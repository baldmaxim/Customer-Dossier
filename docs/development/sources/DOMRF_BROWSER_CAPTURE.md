# Сбор карточки наш.дом.рф через браузер

Для объекта вида `https://наш.дом.рф/сервисы/каталог-новостроек/объект/<id>` агент открывает саму страницу в браузере, ждёт заголовок объекта и раскрывает «Все характеристики». Затем он выполняет выражение из `backend/scripts/domrf-browser-capture.js` в контексте этой вкладки и сохраняет возвращённый объект как JSON. Выражение читает DOM открытой страницы; API и прямой HTTP-запрос не используются.

Проверка без базы:

```powershell
cd backend
npm run registry:preview -- domrf-62087.browser.json
```

Для импорта в портал применяется существующая команда `npm run ingest:once -- --registry-import <ключ> --file <снимок.json>`. Источник должен быть зарегистрирован и допущен к сбору. Формат `domrf-browser@1` распознаётся автоматически; в документе сохраняется адрес именно страницы объекта. Повтор снимка с тем же текстом не создаёт новую редакцию.

Адреса для следующего разбора добавляются в админке: **Источники → Сайты → наш.дом.рф → Карточки**. Там можно указать ID уже существующего объекта портала, посмотреть ожидающие ссылки и запросить повторный снимок. Добавление адреса само по себе не обращается к сайту. Список для агента доступен также командой `npm run ingest:once -- --domrf-pending`. После браузерного чтения агент импортирует JSON командой выше; запись в админке получает отметку «Снимок получен».

## Автоматический сбор через Playwright

Backend поддерживает отдельный фоновый обработчик очереди. На компьютере с активным графическим сеансом установите браузер `cd backend; npx playwright install chromium` и установите `DOMRF_BROWSER_ENABLED=true` в `backend/.env`, затем перезапустите backend. Раз в минуту обработчик берёт одну ожидающую карточку, открывает её в обычном свёрнутом окне Chrome, раскрывает «Все характеристики», читает видимый DOM тем же выражением из `backend/scripts/domrf-browser-capture.js` и передаёт снимок напрямую в импорт. API ДОМ.РФ не используется. Окно закрывается после снимка.

Однократный проход для проверки: `npm run domrf:once` в `backend`. При ошибке админка показывает её текст и кнопку «Повторить сейчас»; автоматические повторы идут с паузой. Сбор требует подтверждённого допуска источника наш.дом.рф. Генподрядчик обязателен для автоматического снимка: если страница его не показала, запись остаётся в очереди с ошибкой.

Фоновый обработчик берёт **уже добавленные URL**. Автоматический поиск URL по названию объекта портала — отдельный этап: совпадение по одному названию небезопасно для разных домов одного ЖК. Для него нужны кандидаты из каталога и проверка адреса и других признаков до записи связи.

## Объекты застройщика (этап 20D)

После карточки объекта обработчик открывает страницы её застройщика и группы компаний в едином реестре застройщиков — по ссылкам из блока застройщика самой карточки (`#KN_DEVELOPER`), а не поиском. Выражение `backend/scripts/domrf-card-capture.js` читает с них реквизиты (ИНН, КПП, ОГРН, юридический адрес, группа) и список объектов; «Показать ещё» раскрывается до конца. Страница застройщика сохраняется отдельным снимком (`domrf-card-browser@1` → запись реестра `developer`), и по ней в канон попадают компания с реквизитами и её группа. Снимок объекта, чья карточка ссылается на эту страницу, получает строку «Застройщик объекта … ИНН …» — по ней публикуется роль застройщика.

**Компании (шаг 2).** Каждую компанию портала — заказчиков и застройщиков первыми — обработчик ищет в едином реестре застройщиков: `/сервисы/единый-реестр-застройщиков?search=<ИНН или название>`, выражение `backend/scripts/domrf-search-capture.js` читает ссылки выдачи. По ИНН выдача — застройщик и его группа; по названию — несколько застройщиков и групп, из них предлагаются только совпавшие с названием компании. За минуту — до трёх поисков в одном окне браузера; первый обход всех компаний — около 16 часов. Решение — в **Источники → Сайты → наш.дом.рф → Компании** (фильтр и поиск по названию; под найденным — строки выдачи и подсказка модели, если оператор разрешил ИИ-обработку источника кнопкой «Разрешить подсказки»): «Это он» отправляет страницу в чтение (дальше — как ниже), «Не он» не возвращается при повторном поиске (раз в 30 дней), «Указать вручную» — ссылка на страницу застройщика или группы, «Искать сейчас» — компания первой в очереди. Компании соответствует одна запись: «Это он» закрывает остальные её записи; «Отменить» снимает решение, а у снятой страницы её ещё не решённые объекты уходят из «Объектов».

Объекты из списков — кандидаты: **Источники → Сайты → наш.дом.рф → Объекты**. Сами они не открываются; оператор подтверждает (ссылка встаёт в очередь выше), отклоняет или заменяет правильной ссылкой. Страницы застройщика и группы перечитываются раз в неделю: новые объекты появляются кандидатами, отклонённые не возвращаются. На сервере обработчик — контейнер `tginfo-domrf` (deploy/README.md).

Снимок связывается с карточкой объекта портала. При первом импорте портал ищет объект по названию и городу. Если нужная карточка уже существует под другим названием, укажите её ID явно:

```powershell
npm run ingest:once -- --registry-import xn--80az8a.xn--d1aqf.xn--p1ai --file domrf-62087.browser.json --project-id 42
```

Команда проверяет, что карточка существует и что этот ID ДОМ.РФ не связан с другой карточкой. При следующем обновлении связь берётся по ID ДОМ.РФ, поэтому изменение названия на сайте не создаёт дубль. Снимки и прежние редакции остаются привязанными к той же карточке. Объединение уже существующих дублей выполняется отдельным механизмом портала с предпросмотром конфликтов.

Профиль `backend/registry-browser-profile.json` оставляет список `objectIds` пустым: обычный проход источника не отправляет запросов к API. Поле `mode: registry_api` требуется существующей схеме импорта; способ получения страницы задаёт браузерный снимок. Источник можно оставить на паузе и обновлять снимки по конкретным ссылкам.

Снимок включает название, адрес, основные и раскрытые характеристики, девелопера, генподрядчика, квартиры и показатели продаж. Навигация, карта и соседние дома не включаются. Раздел «О доме» на сайте помечен как сгенерированный ИИ, поэтому не попадает в первичный текст. Страница объекта не показывает ИНН застройщика: по одному имени связь с компанией не публикуется в канон. Реквизиты берутся со страницы застройщика — отдельным снимком со своей ссылкой (этап 20D, выше).
