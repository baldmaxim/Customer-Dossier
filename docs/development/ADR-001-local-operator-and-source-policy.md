# ADR-001 — Доступ локального оператора, допуск источников, сетевая политика

Статус: принято на этапе 01 (2026-09-14). Следующие этапы сохраняют названия и семантику.
**Дополнение 2026-09-21 (решение владельца):** вход по токену снят с портала на время разработки.
Удалены `api/auth.ts`, `api/operatorToken.ts`, экран входа, хук сессии, CSRF и ключи `OPERATOR_TOKEN`,
`SESSION_IDLE_MINUTES`, `SESSION_MAX_HOURS`. Сохранены и остаются единственной защитой проверки
`Host` (только loopback) и `Origin`/`Sec-Fetch-Site` — они переехали в `api/guards.ts`.
Раздел «Оператор» ниже описывает прежнее решение и сохранён как история: он объясняет, что именно
придётся восстановить, если портал когда-нибудь выйдет за пределы одной машины. Всё остальное
(допуск источников, сетевая политика) действует без изменений.

## Контекст

API был открыт на всех интерфейсах без авторизации; изменяющие операции выполнялись простым
POST с чужой страницы. Сбор и отправка текстов модели не зависели от оснований. Парсер сайтов
открывал любой адрес, включая внутреннюю сеть.

## Решения

**Оператор.** Один локальный оператор. Токен (`OPERATOR_TOKEN` в `backend/.env` или
автоматически созданный `backend/.local/operator-token`) обменивается на серверную сессию
в памяти процесса: cookie `tgi_session` (HttpOnly, SameSite=Strict, Path=/api), простой 2 ч,
максимум 12 ч. CSRF-токен выдаётся в теле ответа входа/сессии, хранится в памяти страницы,
передаётся `X-CSRF-Token` на POST/PUT/PATCH/DELETE. Дополнительно: `Host` только loopback
(DNS rebinding), `Origin` из списка разрешённых, `Sec-Fetch-Site` для запросов без Origin.
Под защитой всё `/api`, кроме `/api/health` и `/api/auth/*`. Рестарт процесса завершает сессии —
для одного оператора это приемлемо. Регистрации, ролей и SSO нет.

Отклонено: токен в localStorage или URL (утечка через XSS, историю, логи); Basic auth
(браузер кэширует и шлёт на любые запросы — CSRF); только CORS (не запрещает отправку).

**Допуск источника.** Колонки `sources.access_status` и `sources.ai_processing_status`
(enum `source_permission`: unknown/approved/blocked/revoked/expired), `policy_scope`,
`policy_basis`, `policy_reference`, `policy_owner`, `policy_decided_at`, `policy_expires_at`,
`is_synthetic`; журнал `source_policy_log`. CHECK: разрешение без основания и ответственного
невозможно. Operational `status` (active/paused/broken) означает только расписание.
Функция `evaluateSourcePolicy` (`backend/src/ingest/policy.ts`) и SQL-эквивалент
`approvedPolicySql` — единственный gate: шедулер, CLI (`--source`, `--probe`, `--probe-site`),
бот, ручная вставка, очередь модели (`claimBatch`), теневой прогон. Новые источники — `paused` +
`unknown`; добавление не делает сетевых запросов.

Будущее (02/05/08B): display/export scope и хранение будут отдельными полями, а не
расширением текущих статусов.

**Сетевая политика.** `backend/src/net/safeFetch.ts` — единственный клиент к источникам:
http/https, порты 80/443, без userinfo, allowlist хостов источника (с поддоменами для сайтов,
точный `t.me` и `api.telegram.org`), проверка IP в собственном `lookup` сокета (запрет
loopback/private/link-local/CGNAT/NAT64/6to4/ULA/multicast/документационных), повторная проверка
каждого редиректа, лимиты времени и размера после распаковки. LM Studio — отдельный фиксированный
адрес из env через `llm/client.ts`, в политику источников не входит.

**Legacy-канон.** До безопасного пути записи (03B) и безопасного слияния (04) изменяющие канон
операции выключены константой в `backend/src/pipeline/guard.ts`, а не переменной окружения.

## Последствия

- Для работы UI нужен токен оператора; без миграции 010 выборки источников падают — миграция
  рабочей базы требует отдельного согласования (и решения по destructive 009, если не применена).
- Все источники рабочей базы после 010 заблокированы до решения оператора.
- Разбор моделью с записью в карточки недоступен до 03B.
