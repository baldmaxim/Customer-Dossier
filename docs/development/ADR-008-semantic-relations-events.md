# ADR-008 — Смысл связей, время и события

Дата: 2026-09-15. Этап 06. Статус: принято.

## Контекст

extract@2 выдавал набор имён, роль на компанию, одну тональность и события без сторон процесса. Связь
компании с объектом не имела своей цитаты (R03), поэтому «А и Б на одном ЖК», «А не является
генподрядчиком» и «А планирует привлечь Б» превращались в одинаковое положительное участие. Даты событий
были днём или ничем, суммы — любым числом рядом, стадия объекта — последней записанной статьёй (R15).

## Решение

### Схема extract@3 и откат

- `llm/semantic/schema.ts`, `llm/semantic/prompt.ts` (`semantic@1`). Роль — у связи, а не у компании.
- Связи: `participation` (компания → объект: роль, корпус, пакет работ, период), `contract` (заказчик
  договора → исполнитель, объект договора как контекст), `corporate` (владение, контроль, группа, бренд).
- События: стороны с процессуальными ролями, номер дела, стадия, результат, интервал даты с точностью,
  сумма строкой с валютой, назначением (claim/award/contract/…) и налоговой базой.
- Полярность (positive/negative) и модальность (reported_fact/claim/planned/possible) — разные поля;
  статус проверки — третье. `negated` в enum остаётся только для legacy.
- Совместное упоминание и совместное участие модель не выводит: это представления над опубликованным
  (`co_participations_v`), не синонимы договора.
- `EXTRACT_SCHEMA_VERSION` (по умолчанию extract@3) входит в отпечаток запуска. extract@2 — откат для новых
  запусков; прежние запуски, ответы и наборы не переписываются, сборка кандидатов понимает обе версии.

### Проверка независима от генератора

`reprocess/semantic/verify.ts` поверх гейта extract@2 (цитата, имя в цитате, ИНН и город из своей цитаты):

- обе стороны связи названы в её цитате **и в одном предложении**; прямой договор без обеих сторон
  в цитате не существует, цепочка А→Б→В не даёт А→В;
- признак вида связи в цитате (договор / участие / владение, контроль, группа, бренд — по виду);
- противоречие смысла цитате — **на проверку**: положительное «состоявшееся» при отрицании, плане или
  слухе; отрицание без отрицания; стадия банкротства не та; одинаковые процессуальные роли; «присуждено»
  без решения. Такой кандидат сохраняется в наборе с причиной и не публикуется;
- дата: год обязан быть в цитате, месяц и день — если написаны; точность понижается до подтверждённой,
  интервал — по точности; дата публикации не подставляется; период связи — открытый, если конец не назван;
- сумма: число с денежной единицей или порядком (млн, руб) во фрагменте, где названа сторона этого
  утверждения, и без чужой компании; валюта — только написанная; НДС и пересчёт не вычисляются;
- корпус — пара «тип + номер» из цитаты; пакет работ — нормализуется (ВК, ОВ, ЭОМ, СС, автоматика,
  противопожарные системы, общестрой) только если тема есть и в подписи, и в цитате, подпись сохраняется;
- номер дела, автор заявления, результат — только если стоят в цитате.

Эвристики словесных признаков не доказывают смысл: они отсекают противоречие ответа и текста.
Семантическое качество модели отдельно измеряет `npm run benchmark:model` на синтетическом корпусе.

### Хранение (миграция 017)

- `assertions`: `polarity`, `context_project_id`, `work_package_label`, `attributed_to`, `case_number`,
  `procedural_role`, `counterparty_role`, `event_stage`, `event_outcome`, `tax_basis`; новые предикаты
  `contract`, `corporate_relation`; неизменяемость содержания расширена. Ключ содержания дополняется
  смысловыми полями только если они отличаются от умолчания — ключи прежних утверждений не меняются.
- Отрицание публикуется отдельным утверждением; если есть такое же положительное о состоявшемся, цитата
  отрицания добавляется к нему как `contradicts` (в составе набора — снимается вместе с ним). Решение
  аналитика не удаляется: основание изменилось — `needs_revalidation`.
- Проекции карточек: роль — только положительное reported_fact (или legacy); событие — положительное
  reported_fact/claim; план, слух и отрицание остаются утверждениями. Дубли одного утверждения из
  нескольких публикаций в событиях схлопываются (`published_assertions_distinct_v`).
- `project_state_history_v` / `project_current_state_v`: состояние объекта по корпусу в действительном
  времени (valid_from), не по времени записи; событие без даты состояния не задаёт.
- `legal_case_events_v`: стадии одного дела группируются по номеру; без номера каждое событие отдельно.
- `review_queue_v`: приоритет 1 идентичность, 2 утверждение и отрицание / два заказчика или генподрядчика
  одного корпуса в пересекающемся периоде, 3 изменившееся основание, 4 оспаривание. Вторая модель не нужна.
- `context_project_id` входит в перенос и `dependencyState` слияния (ADR-005).

### Недоверенный текст

Текст публикации передаётся между маркерами, маркеры внутри текста обезвреживаются, промпт объявляет
текст данными; инструменты модели не передаются, ответ — только JSON по схеме и проходит проверку.
Цитаты хранятся и отдаются как текст.

## Откат

`EXTRACT_SCHEMA_VERSION=extract@2` для новых запусков. Утверждения, доказательства, решения и наборы
не удаляются; публикация прежнего набора — обычной публикацией с ожидаемой версией.
