## Контракт SCOPE_MATCH (`scope-match@1`, `backend/src/dossier/scope.ts`)
Размерности: объект, корпус/очередь, вид работ (нормализованная тема ВК/ОВ/ЭОМ…), роль, период (относительно даты обращения).
Исходы: `match`, `compatible` (обращение размерность не ограничивает), `unknown` (в утверждении не указано — **не подтверждение**),
`conflict`. Корпус нормализуется только по записи («Корп. № 2» = «корпус 2»); синонимы («секция» ≠ «корпус») не выводятся; «весь
объект» из null не выводится (явного признака all_project в схеме утверждений нет — backfill не делался). Дата неизвестна — `unknown`,
не «сегодня».

Правила досье обращения (`dossier-template@2`):
- **Роль установлена** — участие без конфликтов и с известным корпусом при выбранном корпусе. Неизвестная роль/работы/период
  допускаются, но перечислены в пометке «в источнике не указано».
- **Контекст** (`role.context`): участие без корпуса (`role_project_level`), по другому периоду или виду работ (`role_other_scope`),
  отрицание другого корпуса/роли/работ/периода (`role_denied_other_scope`), отклонённое аналитиком отрицание (`role_denied_rejected`).
- **Противоречие** — неотклонённое отрицание без конфликтов по scope. Асимметрия: отрицание по объекту без корпуса остаётся
  противоречием с пометкой и вопросом `contradiction_scope_unknown` (ошибка в сторону проверки, а не ложного подтверждения).
  Решение аналитика противоречие не снимает (T12-11).
- **Цепочка documented** — договор, где компания исполнитель, по этому объекту без конфликтов и с известным корпусом при выбранном.
  Иначе `chain.context` с причиной (объект не назван — общий фон; другой объект; корпус не указан; другой корпус/работы/период),
  статус `scope_unknown`, вопрос «кто заказчик». `differs_from_claim` и суммы — только по применимым договорам.
- Каждая фраза с сопоставлением несёт `scope` (размерности, missing, conflicts) и текстовую пометку.
- **Схема связей**: фильтр корпуса по той же нормализации; ребро без корпуса остаётся с пометкой «корпус в источнике не указан — для …
  не установлено» (`edgeScopeNote`).
- **Снимки**: новые снимки содержат `role.context`/`chain.context` и `scope`; старые payload и hash не меняются, выгрузки и экран
  снимка читают отсутствующие поля как пустые.
