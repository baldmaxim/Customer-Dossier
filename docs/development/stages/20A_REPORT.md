## Исходная проблема

Портал читал только новости; `README.md:276` фиксирует это как ограничение. Связь «объект → юрлицо-застройщик
с реквизитами» добывалась моделью из прессы, где ИНН обычно нет вовсе. Каталог новостроек наш.дом.рф отдаёт
проектную декларацию машиночитаемо (ИНН застройщика, группа компаний, стадия банкротства, признак проблемности).

Три свойства реестра не ложились на сайтовый адаптер: страница — оболочка приложения (селекторы разбирать нечего);
записи не «появляются», а меняются (ценность — в разнице снимков); часть полей изменчива по природе, а утверждение
в каноне неизменяемо. Обоснование и отклонённые варианты — `docs/development/ADR-012-registry-sources.md`.

## Изменения

Миграция `docs/migrations/025_registry_source.sql` (additive): таблица `registry_records` — снимок записи реестра,
одна строка на редакцию (UNIQUE по `revision_id`), триггер неизменяемости с единственным исключением —
`project_id`/`company_id` (их заполнит этап 20B).

Новое, `backend/src/ingest/registry/`:

до заведения источника изменение не влияет ни на что.

## Открытые риски

1. **Доступ к источнику не подтверждён** (подтверждено 403 из среды агента, с машины пользователя не проверялось).
   Severity: блокирует этап целиком. Workaround: официальное API ЕИСЖС по ключу — меняется только профиль,
   код не трогается. Обход WAF не делался и не планируется. Владелец: пользователь.
2. **Имена полей в шаблоне не проверены** — взяты из описания набора данных, а не из живого ответа.
   Severity: средняя, чинится правкой JSON после пробы. Признак — `ok` при нулевом `object_fields`.
3. **Правовая сторона сбора** — допуск ставит оператор с основанием; агент оснований не заполняет.
4. **Рост числа запросов**: реестр перечитывается намеренно. Троттлинг по умолчанию 1 запрос в 4 с,
   `maxItemsPerRun` по умолчанию 20; на живом источнике начинать с одной записи.
