# ADR-016 — Портал от компании: юрлицо → сведения → объекты → публикации

Статус: **принято 02.10.2026** (решения владельца — раздел «Решения владельца»). Этапы 23A–23D — в коде по мере выполнения.

## Контекст

Владелец: «Сейчас всё строится вокруг публикаций Telegram. А должно наоборот — компания; информация о компании
(в том числе проверка в Контур.Фокусе); объекты внутри компании; после этого уже публикации».

Как устроено сейчас (по коду и STATE.md на 02.10.2026):

| Где | Что видно |
|---|---|
| Откуда берётся компания | Только из текста: `resolve/company.ts` — единственное место `INSERT INTO companies`, его зовут конвейер и публикация реестра. Завести компанию самому нельзя |
| Сколько из них юрлица | 2801 карточка, ИНН/ОГРН у 76 (2,7 %). Остальные — имена из постов |
| Каталог на главной | `/api/contractors` читает снимок сигналов (`company_signal_snapshots`), который считается по публикациям; компании без публикаций по умолчанию скрыты (`includeInsufficient=false`), компании новее снимка не видны вовсе |
| Главная | Переключатель «Компании / Публикации» — лента равноправна каталогу |
| Карточка | «Обзор» — плитки из публикаций (события, публикации, связи, суды); ЕГРЮЛ — три строки в шапке и пятый раздел «Подробно» |
| Контур.Фокус, ДОМ.РФ | Работают по реквизиту — то есть только у тех 76. Остальным карточкам спросить нечего |

Итог: компания — побочный продукт текста. Портал не может ответить «как дела у Заказчика», если о Заказчике
не писали в собранных каналах, и не может спросить ЕГРЮЛ о компании, у которой из текста не пришёл ИНН.

## Решение (предлагаемое)

### 1. Новая единица портала — юрлицо с реквизитом

Компания = ИНН/ОГРН с верной контрольной суммой (`entity_identifiers`). Всё прочее прикрепляется к ней
в порядке надёжности:

1. **Юрлицо** — реквизиты; наименование по ЕГРЮЛ.
2. **Сведения** — ЕГРЮЛ из Фокуса: статус, руководитель, адрес, ОКВЭД, капитал, учредители. Позже —
   суды, банкротство, ФССП, СРО, аффилированность (каждый метод — отдельное решение по тарифу, ADR-015 п. «Последствия»).
3. **Группа** — учредители и дочерние (ЕГРЮЛ), группа компаний (ДОМ.РФ).
4. **Объекты** — ДОМ.РФ по ИНН застройщика и объекты, где компания названа в публикациях (роль — из текста).
5. **Публикации** — подтверждение и контекст: утверждения конвейера о компании и о её объектах.

Карточка без реквизита — не компания, а **упоминание**: имя из текста, которое ждёт опознания.

### 2. Компанию можно завести самому

`POST /api/companies { identifier }`: контрольная сумма → уже есть карточка с этим реквизитом — вернуть её
(не дубль) → иначе новая карточка `entity_type = legal_entity`, реквизит с `origin = 'manual'`, отметка
«на контроле» и сразу запрос Фокуса (если ключ задан), без ожидания расписания. Наименование до ответа Фокуса —
«ИНН …»; после — наименование ЕГРЮЛ (полное и краткое) становится алиасом карточки. Тогда поиск находит её
по названию, а резолвер прикрепляет к ней новые публикации по прежним правилам (упоминание без формы и
реквизитов — к юрлицу с реквизитами, несколько равных кандидатов — неоднозначность, не выбор первого).

«На контроле» (`company_watch`: компания, кто, когда; снятие — отметкой, без удаления) поднимает компанию
в очередях Фокуса и ДОМ.РФ. Таблица ссылается на компанию — входит в перенос `entityMerge.ts` и `dependencyState`.

### 3. Публикации назначаются компаниям; спорное решает человек

Конвейер по-прежнему разбирает каждую публикацию. Упоминание, которое резолвер уверенно узнал (реквизит,
форма и имя юрлица), прикрепляется к существующей компании, как и раньше. Всё остальное — **упоминание**:
техническая карточка без реквизита (provisional-сущность резолвера, ADR-005 — она нужна, чтобы утверждения
было к чему привязать), которая в каталог компаний не входит и ждёт решения человека:

- **«Это компания X»** — X уже есть в портале: слияние упоминания в X через предпросмотр
  (`resolve/entityMerge.ts`, рубильник `MERGE_APPLY_ENABLED`); утверждения и публикации переходят к X;
- **«Это юрлицо с ИНН …»** — реквизит `origin = 'manual'` на саму карточку: она становится компанией,
  Фокус приносит ЕГРЮЛ; ИНН уже у другой карточки — это «Это компания X»;
- **«Не компания»** / **«Отложить»** — решение записывается, упоминание уходит из очереди.

Кандидаты для решения: похожие юрлица портала (бесплатно), подсказки Контур.Фокуса по названию
(метод `suggest` — автоматически, в пределах `FOCUS_DAILY_LIMIT`, сначала упоминания с большим числом
публикаций) и уже работающий поиск в реестре застройщиков ДОМ.РФ. Кандидат — не решение: ни реквизит, ни
слияние без человека не применяются. Модель реквизит не угадывает; ИНН из текста по-прежнему принимается
только из подтверждённой цитаты.

### 4. Экраны

- **Меню**: «Компании · Связи · Админка». Главная — «Компании» без переключателя «Публикации»; общей ленты нет:
  публикации видны на вкладках компании и объекта, страница публикации открывается оттуда.
- **Главная «Компании»**: поиск по названию и ИНН; введён ИНН, а карточки нет — «Добавить компанию по ИНН».
  Список читает реестр юрлиц, а не снимок сигналов: Компания (ЕГРЮЛ) · ИНН · Статус ЕГРЮЛ · Город · Объектов ·
  Публикаций · Последняя публикация. Фильтры: «На контроле», роль. Вкладка «Без ИНН (N)» — упоминания с числом
  публикаций и кандидатами, решение — в карточке упоминания.
- **Карточка**: вкладки по порядку сути — «Сведения» (ЕГРЮЛ целиком, «было — стало», группа и учредители,
  реестр застройщика) · «Объекты» · «Публикации» · «Подробно» (события, показатели, резюме, схема). Открывается
  на «Сведениях». Шапка — наименование ЕГРЮЛ, реквизиты, статус, руководитель, адрес, «На контроле».
- **Карточка упоминания**: вместо ЕГРЮЛ — «Юрлицо не установлено» с кандидатами и «Это он».

### 5. Что не меняется

Сбор, конвейер, канон, цитаты, утверждения и решения аналитика, правила слияния, сигналы (`signals@2` уходят
в «Подробно»), Фокус и ДОМ.РФ как справочники вне канона (ADR-012, ADR-015), админка источников.
Оценок надёжности нет (ADR-009): статус ЕГРЮЛ — словами.

## Решения владельца (02.10.2026)

1. Каталог по умолчанию — юрлица с реквизитом; имена без ИНН — отдельной вкладкой «Без ИНН».
2. «Публикации должны разбираться и после разбора назначаться в существующие компании. В спорных моментах
   решает человек» — п. 3: новое имя из текста не становится компанией каталога, пока его не назначит человек.
3. Общей ленты нет: публикации — только в компании и объекте.
4. Подсказки Фокуса по названию — автоматически, в пределах суточного лимита.

## Последствия

- Каталог по умолчанию станет короче (юрлиц мало), пока не пройдёт опознание и оператор не заведёт своих Заказчиков.
- Расход тарифа Фокуса растёт с числом заведённых компаний и с поиском по названию; лимит `FOCUS_DAILY_LIMIT` прежний.
- «Это компания X» — слияние: без `MERGE_APPLY_ENABLED=true` на сервере назначение упоминания в существующую
  компанию не применяется (предпросмотр работает, экран говорит почему). Включение — правка .env владельцем.
- Алиасы ЕГРЮЛ меняют поведение резолвера: новые публикации чаще прикрепляются к юрлицу. Уже опубликованное
  не перепривязывается — только новым разбором или слиянием.
