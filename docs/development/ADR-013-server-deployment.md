# ADR-013 — Серверная выкладка: вход оператора и сервер quantor

Статус: принято 30.09.2026 (решение владельца: публичный домен со входом, Telegram через nl3,
модель остаётся на домашнем ПК).

## Контекст

Портал жил на одной машине оператора: API только на loopback, входа нет (снят 21.09.2026, `7eeff42`),
«Портал не выставляется наружу; вернуть вход — отдельная задача». Владельцу нужен доступ с телефона и
из других мест, а домашний компьютер не обязан работать круглосуточно.

Замер 29–30.09.2026:

- **Первая машина Selectel** (1 vCPU / 2 ГБ, 24 контейнера, своп занят на 905 МБ, диск на 72 %) —
  места нет; её апгрейд уже отклонил Quantor (его ADR-0032).
- **quantor** (2 vCPU / 4 ГБ / 50 ГБ) — занято 1.1 ГБ, свободно 41 ГБ диска; пределы памяти
  Quantor ≈ 3.1 ГБ, реальное потребление ≈ 0.6 ГБ.
- **Telegram с Selectel недоступен**: `t.me` и `api.telegram.org` — таймаут по IPv4, маршрута IPv6
  нет, на обоих серверах. С nl3 (Нидерланды, AmneziaWG) открывается.
- **Видеокарты на сервере нет**: Qwen3-8B остаётся на домашнем ПК.

## Решение

1. **Два режима входа, `AUTH_MODE`.** `none` (по умолчанию) — локальная работа как раньше: loopback,
   без входа. `token` — сервер: токен оператора (`OPERATOR_TOKEN`, ≥ 32 символов) меняется на серверную
   сессию в памяти процесса; cookie `__Host-tgi_session` (HttpOnly, SameSite=Strict, Secure, Path=/),
   CSRF-токен в памяти страницы, все маршруты `/api`, кроме `health` и `auth`, — только после входа,
   включая «не найдено». Перезапуск API — повторный вход: для одного оператора это дешевле таблицы.
   Код входа — восстановленный из `7eeff42^` с правками под публичный адрес (`api/auth.ts`).
2. **Сеть без входа конфигурацией не собирается.** `HOST` вне loopback — только при `AUTH_MODE=token`;
   `PUBLIC_ORIGIN` вне loopback — только https и только со входом (`config/parse.ts`). Хост из
   `PUBLIC_ORIGIN` — единственное имя, кроме loopback, которое пропускает проверка Host
   (`api/guards.ts`); сам адрес — допустимый Origin. На сервере режим, адрес и доверие прокси зашиты
   в `deploy/docker-compose.yml`, а не в `.env`.
3. **Один доверенный прокси, `TRUST_PROXY`.** `infra-nginx` перезаписывает `X-Forwarded-For` адресом
   клиента, `tginfo-web` передаёт его как есть, API берёт адрес оттуда. Иначе лимит попыток входа
   считался бы по адресу прокси: перебор с одного адреса запирал бы вход всем.
4. **Сервер quantor рядом с Quantor.** Свой compose-проект `tginfo`, своя база (postgres:17), ни одного
   порта наружу; вход — через общий `infra-nginx` Quantor по сети `infra_web`. Пределы памяти
   ≈ 0.9 ГБ (db 384m, api 448m, web 32m). Образы собираются на машине разработки и приходят `docker load`.
5. **Telegram — сплит-туннель AmneziaWG до nl3** только для сетей Telegram (`AllowedIPs`), без смены
   DNS и маршрута по умолчанию. Код не меняется: `net/safeFetch.ts` видит обычные публичные адреса.
   Прокси в `safeFetch` не добавляем — он спорил бы с запретом внутренних адресов.
6. **Модель — обратный SSH-туннель** с домашнего ПК на шлюз внутренней сети `172.30.0.1:1234`.
   Пользователь без оболочки, ключ с `permitlisten`, ufw пускает к порту только 172.30.0.0/24.
   ПК выключен — портал и сбор работают, разбор ждёт (этап 22).

## Последствия

- Локальная работа, тесты и `pilot:check` не меняются: по умолчанию `AUTH_MODE=none`, пилотный манифест
  по-прежнему требует loopback — пилот с третьей стороной и рабочий сервер оператора разные вещи.
- `release:manifest --compare` при переносе базы на сервер покажет `CONFIG_MISMATCH` по `HOST` — это
  ожидаемо; ключи входа в манифест не входят, `OPERATOR_TOKEN` — в запрещённом списке.
- Память сервера делится с Quantor. Реальное потребление обоих ниже пределов; если воркер Quantor
  начнёт получать тяжёлые PDF и доступно станет меньше 500 МБ — тариф 8 ГБ без переезда.
- Сессии в памяти: один процесс API, одна реплика. Второй оператор с разными правами — отдельная задача.
- Выкладка и откат — `deploy/README.md`.

## Отклонённые варианты

- **Первая машина Selectel** — нет памяти и диска.
- **Только SSH-туннель без домена** — без правок кода, но владелец выбрал доступ с телефона по адресу.
- **Basic auth на nginx вместо входа в портале** — пароль в каждом запросе, нет выхода и CSRF-защиты
  изменяющих запросов, 401 от nginx ломает PWA.
- **HTTP-прокси для Telegram в `safeFetch`** — правка SSRF-клиента ради маршрута, который решается сетью.
