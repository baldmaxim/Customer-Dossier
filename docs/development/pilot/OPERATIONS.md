# Пилот: проверка человеком, остановки, копии, хранение, обновление

Дополняет `LOCAL_RUNBOOK.md` (эксплуатация, копия и восстановление) и `sources/SOURCE_PROFILE_CONTRACT.md` (подключение).
Ничего здесь не включается автоматически: расписаний, фоновых копий и очистки нет; время и включение задаёт владелец.

## 1. Последовательность пилота (всё вручную, по одному шагу)
1. `pilot:check` → READY_TO_START (иначе стоп). Фоновые флаги false, loopback.
2. Сбор: `npm run ingest:once -- --source <ключ>` по каждому источнику манифеста, не больше лимита окна.
3. ИИ: только для источников из `allowedSteps.ai` — постановка редакций на экране «Запуски» или `pipeline:once -- --reextract --limit N --source <ключ>`;
   выполнение `pipeline:once` (не `--loop`); отказы и неполные запуски — в карточке запуска.
4. Проверка человеком каждого набора до публикации: карточка запуска → кандидаты с цитатой, редакцией и вердиктом → неоднозначные
   упоминания (15A) → предпросмотр (15B) → публикация по токену предпросмотра. Групповой публикации и «подтвердить всё» нет.
5. Решения по утверждениям — по одному в очереди проверки (причина обязательна). Новая редакция или изменение оснований
   возвращают утверждение в «нужен пересмотр».
6. Обращение → досье → «Кратко для переговоров» → снимок → выгрузка. Руководитель видит статусы, основания и ограничения.
7. Замер пилота (таблица `evidence/19/USER_RUN.md` раздел D) — результаты этой выборки, не полнота интернета.

Что видит проверяющий: источник, цитату и редакцию (`AssertionDetail`, карточка запуска), scope относительно обращения, отрицания
и противоречия, юридическую идентичность и неоднозначности, число публикаций и семей перепечаток, «есть более новая редакция».

## 2. Условия остановки
Остановить новые изменения данных (не публиковать, не собирать, не разбирать), сохранить логи, снимки, выгрузку JSON и описание:
- ложная идентичность (чужое юрлицо в досье) или чужой договор/роль в выводе;
- нарушение допуска: вызов модели или сбор после отзыва, источник вне манифеста;
- потеря решения аналитика, изменение неизменяемых строк (редакции, доказательства, решения, снимки);
- снимок, чей hash не подтверждается (`Целостность НЕ подтверждена`);
- тихая частичная публикация (опубликован набор неполного запуска);
- restore не MATCH, неверная цель, отказ preflight.
Дефект оформить в `BACKLOG.md` (ID, severity, шаги, артефакты). Рабочую базу «фоном» не чинить: исправление — кодом, проверка — на тестовой цели.
Прочие промахи (пропуск факта моделью, неполный текст источника) — в BACKLOG с областью и обходом, пилот не останавливают.

## 3. Резервная копия и учения по восстановлению
Процедура — `LOCAL_RUNBOOK.md` §5–6 и `evidence/09/USER_RUN_CLOSURE.md` раздел E (порядок: писатели остановлены → `release:manifest --out`
и `release:check --out` → `pg_dump -Fc` внутри контейнера и `docker cp` без перенаправлений PowerShell → restore в **отдельную
размеченную цель** с `--exit-on-error --single-transaction` → `release:manifest --compare` MATCH → чтение через приложение).
Перед пилотом на рабочей базе — копия и учения обязательны. Замер (`release:bench`) пишет снимки: не между baseline и дампом.

Шаблон ручной копии (не расписание, запускает владелец):
```powershell
# Цель: копия базы <ИМЯ> перед шагом пилота. Побочный эффект: файл дампа в каталоге копий. Проверка цели: current_database() и маркер.
$stamp = Get-Date -Format 'yyyyMMdd-HHmm'
docker exec tg-info-test-db pg_dump -U tg_test -d tg_info_test -Fc -f "/tmp/pilot-$stamp.dump"
if ($LASTEXITCODE -ne 0) { throw 'pg_dump failed' }
docker cp "tg-info-test-db:/tmp/pilot-$stamp.dump" "$env:USERPROFILE\tg-info-backups\pilot-$stamp.dump"
```
Для рабочей базы имя контейнера, роль и базу подставляет владелец после идентификации; пароли в команды и логи не пишутся.

## 4. Хранение
| Данные | Класс | Автоудаление |
|---|---|---|
| `source_runs`, `extraction_chunk_responses.raw_response`, `http_cache`, диагностика | сырые попытки | нет; срок — `retention.rawAttemptsDays` манифеста, очистка — ручная процедура после решения владельца |
| `document_revisions`, `evidence`, `assertions`, `review_decisions`, `ambiguity_decisions`, `entity_merges`, `dossier_snapshots`, история обращений | доказательная база | **никогда автоматически**; удаление запрещено триггерами/контрактом, правка снимка — только вымарывание с журналом |
Отзыв допуска источника: новые вызовы и сбор прекращаются (этапы 01, 11); сохранённые материалы остаются и показываются по
текущему допуску (снимки — вымарывание цитат при выдаче). Удаление по отзыву — отдельное решение владельца о правах хранения.

## 5. Обновление локального приложения
1. Копия (§3) и `release:manifest --out` до обновления.
2. `git pull` нужного коммита; `npm ci` в обоих пакетах; `npm run typecheck`, `npm test` (backend и frontend), `npm run build`.
3. `npm run migrate -- --dry` на целевой базе: список pending и destructive. Additive миграции тестовой цели — `npm run migrate`.
   **Рабочая база: миграция только после её идентификации и отдельного явного разрешения** — пилот таким разрешением не является.
4. Канареечная проверка на тестовой цели: `npm run test:integration`, `seed:test-brief`, открыть обращение и снимок.
5. Откат кода/конфига: `git checkout <прежний коммит>`, `npm ci`, перезапуск; новые таблицы и колонки additive-миграций прежний код
   игнорирует. Откат данных — только восстановлением копии в отдельную цель и осознанным переключением; история не удаляется.
