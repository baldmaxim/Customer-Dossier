# ADR-006 — Адаптеры сайтов по профилю, догоняющий обход и здоровье источника

Статус: принято на этапе 05A (2026-09-15).

## Контекст

Сайты читались только через RSS: `listSelector` был объявлен, но не использовался; анонс длиннее 400 символов не
дополнялся статьёй; сбой, 403, 429, смена вёрстки и «новостей нет» в запуске не различались; курсора обхода и
условных запросов не было; в админке — «найдено/новых» и последняя ошибка.

## Решение

Миграция `015_website_adapters.sql`, модуль `backend/src/ingest/sites/`.

1. **Профиль источника** (`profile.ts`, `sources.config`) — строгая zod-схема без неизвестных ключей: режим
   `rss | html_list`, адрес ленты и контракт `rssContentIsFull`, стартовые страницы, селекторы списка/статьи/карточки
   объекта, пагинация с `maxPages`, дополнительные хосты, отбрасываемые query-параметры, зона дат, лимиты записей,
   байт, времени и паузы, `refetchKnown`, ожидаемый минимум записей на странице. В профиле нет кода, регулярных
   выражений и shell: селектор — строка cheerio, символы `{ } < \`` запрещены. Старый конфиг `{rss, articleSelector}`
   приводится к режиму rss; `listSelector` без профиля отвергается. Профиль записывается командой
   `--site-profile <ключ> --file` или `PUT /api/admin/sources/:id/profile` только после проверки схемой.
2. **Сеть** — только `safeFetch`: allowlist из хостов профиля, проверка каждого редиректа, размер и время из профиля.
   Для тестов — внедрённый транспорт (`ISafeFetchDeps.transport`, `setSiteTransportForTests`): подменяется только
   сам запрос, проверки адреса, редиректов и размера применяются к ответу так же. Production-политика не ослаблена.
3. **Исходы запроса** (`fetcher.ts`): `ok`, `not_modified` (304 по ETag/Last-Modified из `http_cache`), `http`
   (429/503 с `Retry-After`), `policy`, `dns`, `network`, `timeout`, `oversize`. Итог запуска: `ok`, `not_modified`,
   `partial`, `parser_degraded`, `rate_limited`, `blocked` (401/403/451 и запрет политики — без обхода), `http_error`,
   `network`, `oversize`, `config_invalid`.
4. **Обход** (`crawler.ts`) `discover → fetch → parse → persist/observe`:
   - rss: лента из профиля или объявленная `<link rel=alternate>` на главной; content:encoded полон только по
     контракту; иначе статья со страницы по `bodySelector`;
   - html_list: страницы по `nextSelector` до `maxPages`; записи страницы, `http_cache` и курсор
     (`cursor.site.backlogNext/caughtUp`) сохраняются одной транзакцией — курсор не уходит за несохранённую страницу;
     после сбоя следующий запуск читает свежие страницы («головная фаза», не расходует бюджет страниц и не переписывает
     курсор хвоста) и продолжает с недочитанной; после полного прохода — `caughtUp`, остановка на первой странице без
     новых записей;
   - статья: `bodySelector` найден — full (признак обрезки — excerpt); не найден — «неизвестно»; сбой запроса или
     ссылка вне allowlist — честный анонс (excerpt с причиной) только для новой публикации, известная версия анонсом
     не заменяется; таблицы, PDF, изображения, видео — вложения `unsupported`, не скачиваются;
   - карточка объекта (`projectCards.urls`) — публикация с текстом полей в стабильном порядке: повтор без изменений —
     наблюдение `unchanged`, не новая «новость»;
   - пустой список на большой странице или меньше ожидаемого минимума — `parser_degraded` с причиной, курсор не
     двигается; пустая корректная лента — `ok` с покрытием `empty_feed`.
5. **Даты** (`dates.ts`) — записанное правило: зона в строке — `exact`; без зоны — зона профиля (`local_tz`); без
   времени — `date_only`; без года, «вчера», «2 часа назад» — дата не выставляется (`no_year`/`relative`); сырой текст
   в `document_revisions.published_at_raw`, точность — `published_at_precision`.
6. **Наблюдаемость.** `source_runs`: исход, найдено/сохранено/изменено/пропущено/ошибок, страницы, покрытие (причина
   остановки, недочитанный хвост, пометка о неполной истории), версия парсера, `retry_after_at`, длительность.
   `sources`: `health`, `health_reason`, `last_attempt_at`, `parser_version`. `source_observations.parser_version`:
   смена вёрстки при том же тексте — наблюдение, не редакция. 429 откладывает следующий запуск до `Retry-After` без
   роста `fail_streak`; `partial` не считается неудачей, но здоровье — `error` с причиной.
7. **Проба** (`probe.ts`): уже допущенный сайт, одна страница, до трёх записей, без записи в базу, без условных
   заголовков, без включения опроса и изменения допуска (`--probe-site`, `POST /api/admin/sources/:id/probe`).

## Последствия

- Для реальных сайтов нужен проверенный профиль; сид-источники остаются на паузе без допуска (`LIVE_SOURCE=NOT_RUN`).
- Лента и лимит страниц не гарантируют полноту истории — это видно в покрытии, а не скрыто.
- Headless-браузер не добавлен: ни один разрешённый сайт его не требует.

## Откат

Пауза конкретного источника (`status=paused`) — тексты, редакции и история запусков сохраняются. Поломка парсера не
удаляет прежние данные: при `parser_degraded` новые записи не пишутся, курсор не двигается.
