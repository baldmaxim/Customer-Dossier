# ADR-015 — Контур.Фокус: сведения ЕГРЮЛ по реквизиту, а не источник публикаций

Статус: принято 2026-10-02 (код есть; включение — ключ API от владельца).

## Контекст

Портал отвечает на вопрос «как дела у Заказчика», но о самой компании знает только то, что написали в
публикациях и в проектной декларации (ADR-012). Действует ли юрлицо, кто им руководит, не идёт ли ликвидация,
где оно зарегистрировано — этого в новостях почти нет, а в ЕГРЮЛ есть. Владелец попросил подключить
Контур.Фокус (focus.kontur.ru), чтобы получать свежие сведения.

У Фокуса три свойства, которые определяют решение:

1. **Это платный API по ключу** (`https://focus-api.kontur.ru/api3/<метод>?key=…&inn=…`): каждый запрос
   списывается с тарифа. Веб-интерфейс focus.kontur.ru требует входа — читать его программой нельзя и не нужно.
2. **Спрашивают по реквизиту.** Метод получает ИНН или ОГРН и отвечает списком найденных компаний.
   Тексты публикаций туда не уходят — только реквизит компании, публичный идентификатор.
3. **Сведения изменчивы**: руководитель, адрес, статус («в стадии ликвидации») меняются. Канон неизменяем,
   и конвейер «умеет добавлять факты, но не отзывать их» — та же причина, по которой изменчивое из реестра
   ДОМ.РФ остаётся снимком (ADR-012).

## Решение

Миграция `040_kontur_focus.sql`, модуль `backend/src/focus/`, ключ — `settings/focusKey.ts`.

1. **Не источник, а справочник.** Фокуса нет в `sources`: допуск источника (`ingest/policy.ts`) отвечает на
   вопрос «можно ли читать эту ленту», а здесь читать нечего. Допуск — ключ, который задаёт администратор
   (право `focus.manage`, как ключ OpenRouter — деньги счёта), и рубильник `FOCUS_ENABLED`. Без ключа нет ни
   одного запроса при любом флаге.
2. **Сеть — `net/safeFetch`**: один разрешённый хост `focus-api.kontur.ru`, без перенаправлений (ключ стоит
   в адресе и не должен уехать по редиректу). Ключ не попадает ни в лог, ни в журнал, ни в текст ошибки —
   тело ответа обрезается и ключ в нём замазывается.
3. **Два метода**: `req` (наименование, статус, руководители, юридический адрес, коды) и `egrDetails`
   (основной ОКВЭД, уставный капитал, учредители, правопредшественники). Компанию, которую Фокус не знает по
   `req`, `egrDetails` не спрашивает. 401/403 на `req` — ключ не принят, проход останавливается; на `egrDetails`
   — метод вне тарифа, в этом проходе он больше не спрашивается, сведения `req` сохраняются.
4. **Снимок ответа, а не канон.** `focus_records` хранит элемент ответа целиком; новая строка — только когда
   ответ изменился (`sha256-canonical-json@1`). Карта полей (`focus/map.ts`, `focus-map@1`) применяется на
   чтении: правка карты не требует повторного платного запроса. «Что изменилось» — разница соседних снимков на
   чтении, отдельной таблицы изменений нет. В `assertions`/`evidence` сведения Фокуса не идут.
5. **Без ссылок на компании.** Таблицы ключуются реквизитом (`identifier_type`, `identifier`), компания
   находится по реквизиту при чтении (как реестр ДОМ.РФ, этап 20D). Слияние компаний их не переносит и
   висячих ссылок не оставляет; `entityMerge.ts` не меняется.
6. **Какой реквизит.** Только `entity_identifiers` с верной контрольной суммой; ИНН главнее ОГРН/ОГРНИП. Два
   разных ИНН у одной карточки — вопрос опознания, а не повод платить за оба: такая компания не спрашивается,
   экран говорит почему. Одинаковый реквизит у двух карточек (дубль до слияния) — один запрос.
7. **Расход под контролем.** `FOCUS_DAILY_LIMIT` (по умолчанию 100) — успешных запросов за скользящие сутки,
   расписание и кнопка вместе, по журналу `focus_requests`; компания стоит два запроса. Срок повторной проверки
   — `FOCUS_REFRESH_DAYS` (14). Очередь расписания: заказчики и застройщики первыми, среди них — ни разу не
   спрошенные, затем самые давние. Сбой Фокуса — пауза до повтора час за каждую неудачу подряд, не больше суток;
   неудачи тариф не тратят. Тариф исчерпан (402) или «слишком часто» (429) — проход останавливается.
8. **Без оценок.** Экспресс-отчёт Фокуса («зелёные/жёлтые/красные» факты), скоринг и аналитические методы карта
   не читает и база не примет (`focus_records_method`): итоговой оценки надёжности в портале нет (ADR-009).
   Статус ЕГРЮЛ показывается словами, без цвета.
9. **Экран.** Шапка карточки — «Статус в ЕГРЮЛ», «Руководитель», «Юридический адрес» с подписью «ЕГРЮЛ по данным
   Контур.Фокуса, проверено <дата>». «Подробно» → «ЕГРЮЛ — Контур.Фокус»: все строки, атрибуция, «было — стало»,
   ссылка на карточку в самом Фокусе (только `https://focus.kontur.ru`), «Обновить из Контур.Фокуса» — с
   `sources.manage`, не чаще раза в 10 минут на компанию. Админка → Источники → Сайты → Контур.Фокус
   (`/admin/sources/focus`): расход за сутки, покрытие, ключ, журнал последних запросов.

## Последствия

- Карта полей написана по известной структуре ответов API, а не по живому ответу: ключа у агента нет.
  Перед включением — `npm run focus -- --probe <ИНН>` (имена полей ответа и строки карточки; два запроса
  тарифа, снимков не пишет). Не совпало — правится `focus/map.ts`, сохранённые ответы перечитываются сами.
- Ключ из админки шифруется так же, как ключ OpenRouter (`app_secrets`, AES-256-GCM от пароля базы); сменили
  пароль базы — ключ вводят заново. `FOCUS_API_KEY` в .env — запасной путь.
- Реквизиты компаний уходят внешнему сервису. Тексты публикаций — нет. Пилот по манифесту (этап 19) с
  `FOCUS_ENABLED=true` блокируется, как и другие фоновые задания.
- Новые методы Фокуса (арбитраж, банкротство, исполнительные производства) — это новые строки CHECK
  `focus_records_method`, новая карта и новый расход тарифа: отдельное решение, а не правка списка.
- Откат: `FOCUS_ENABLED=false` (остаётся кнопка) и удалить ключ в админке — запросов нет; собранные снимки
  остаются в базе и на карточке.
