# ADR-018 — Сайты компаний: веб-поиск находит, человек подтверждает, портал читает

Статус: принято 2026-10-06. Этап 25A — поиск и подтверждение. Этап 25B — чтение подтверждённого сайта (дополнение
ниже, когда будет сделано). Включение — флаг и проба владельца.

## Контекст

Владелец (06.10.2026): «для каждой компании проверять и их личные сайты; нейронка пробегает по интернету в поисках
сайтов, человек подтверждает и привязывает к заказчику, оттуда видим объекты — текущие и новые». Публикации и ДОМ.РФ
не показывают проекты, которые компания анонсирует у себя раньше всех. Колонка `companies.website` (миграция 005)
никем не заполнялась.

Решения владельца:

- поиск — веб-плагин OpenRouter (Exa): ключ и туннель уже есть, около $0,01 за поиск;
- push-уведомлений нет;
- найденный сайт можно открыть до подтверждения, чтобы проверить реквизит, — исключение из правила «без допуска
  живых запросов нет».

Этот этап заменяет запланированный «24G Сайт компании» (поле сайта и проверка доступности).

## Решение (этап 25A)

Миграция `045_company_sites.sql`, модуль `backend/src/companySites/`, промпт `llm/siteSearch/` (`site-search@1`).

1. **Модель предлагает — поиск подтверждает — решает человек.**
   - Запрос — одна строка: имя, ИНН, город и до двух объектов компании (`formatSiteSearchQuery`). Правила — в
     системном сообщении. Плагин ищет по сообщению пользователя, поэтому маркеров `<<<ТЕКСТ>>>` там нет.
   - Адрес из ответа модели принимается, только если его хост был среди страниц выдачи (`message.annotations`,
     `url_citation`) или является корнем такого хоста (`companySites/url.ts::acceptCandidates`). Это аналог правила
     «цитата есть в тексте»: адрес, который модель придумала, до оператора не дойдёт.
   - Выдача пуста — исход `no_citations`, предложения модели отбрасываются; повтор поиска — через 7 дней, а не через 90.
   - Справочники реквизитов, агрегаторы новостроек, соцсети, СМИ и госсайты сайтом компании не считаются.
2. **Проверка кандидата до решения** (`companySites/verify.ts`) — исключение из правила допуска, решение владельца.
   - Через `safeFetch` открываются только хост кандидата и его поддомены: главная и до трёх страниц, ссылки на которые
     похожи на «Контакты / О компании / Раскрытие / Документы».
   - Признаки: ИНН и ОГРН компании (только с верной контрольной суммой), ядро названия, другие ИНН после слова «ИНН».
     Текст страниц не хранится — только признаки и заголовок главной.
   - Исходы различаются: запрет, недоступность, перенаправление на другой сайт, страница только на JS, не HTML. Ни один
     из них не превращается в «сайт проверен».
   - Сеть без модели — проход идёт в тике сбора (`INGEST_ENABLED`), 1,5 с между страницами одного сайта.
3. **Очередь** (`company_site_searches`) — по образцу поиска в реестре ДОМ.РФ (ADR-012 п. 27):
   - аренда 10 минут; роли — через `WITH roles AS MATERIALIZED`;
   - ищутся юрлица с реквизитом и группы; порядок: «на контроле» → срок → заказчики и застройщики → с реквизитом → группы;
   - не ищем, пока у компании есть кандидат, ждущий решения: сначала решение, потом новый платный поиск;
   - не ищем СЗ, у группы которых сайт подтверждён (утверждение «входит в группу» — те же условия, что `MEMBERS_SQL`):
     на карточке СЗ показан сайт группы;
   - название без отличительных слов не ищется — пометка «укажите вручную».
4. **Расход.** Каждая попытка — платный поиск. Место в суточном лимите (`SITE_SEARCH_DAILY_LIMIT`) резервируется до
   запроса под общей блокировкой; журнал — `site_search_requests`, без ссылки на компанию. Повтор — только при ответе не
   по схеме (один, при temperature 0, тоже за место в лимите). Сбой модели не повторяется: компания встаёт на паузу.
   Лимит исчерпан — компания возвращается в очередь через час, неудачей это не считается.
5. **Решения** (`sources.manage`: поиск стоит денег, подтверждённый сайт в 25B станет источником):
   - «Это сайт компании» и «Не он» — повторное решение даёт 409;
   - «Отвязать» у подтверждённого — с вопросом;
   - «Указать вручную» — адрес сразу подтверждён, проверка — следующим проходом;
   - «Искать снова» ставит компанию в начало очереди.

   У компании может быть несколько подтверждённых сайтов (сайт группы и сайт СЗ). Отклонённый хост при повторном поиске
   не возвращается и находкой не считается. Тот же хост, подтверждённый у другой компании, показан оператору.
6. **Только OpenRouter.** Плагин уходит в тело запроса только у спецификации `SITE_SEARCH_SPEC`
   (`IExtractSpec.plugins`). У LM Studio — отказ без запроса. Идентичность исполнения запусков разбора
   (`reprocess/provider.ts`) не меняется: она хэширует промпты, а не тело запроса. Проход идёт тем же заданием, что
   разбор, — последним (`PIPELINE_ENABLED`), и только при `SITE_SEARCH_ENABLED=true` (по умолчанию false).
7. **Канон не трогается.** `companies.website` не пишется: второй источник правды слияние не перенесло бы. Сайт —
   сведение оператора о компании, а не утверждение с цитатой. Кандидаты и поиск переносятся слиянием (`entityMerge.ts`):
   тот же хост у цели — строка источника удаляется с образом; поиск — один на компанию.
8. **Проба до включения**: `npm run site-search -- --probe <ИНН>` (на сервере — `node dist/companySites/cli.js`) —
   один платный поиск без записи кандидатов. Проверяет, приходят ли `annotations` вместе со строгой JSON-схемой и
   принимает ли маршрут с `require_parameters` плагин. В документации OpenRouter это не описано.

## Последствия

- Тексты запросов (имя, ИНН, город, названия объектов) уходят OpenRouter и поисковику Exa. Это публичные сведения, а
  не тексты публикаций, но внешняя передача — да. `pilot-manifest@1` её запрещает; пилот с флагом не совместим.
- Поиск ошибается в сторону «не нашлось»: адрес вне выдачи отбрасывается, даже если он верный. Такой адрес оператор
  указывает вручную.
- Сайты на JS без браузера не читаются (`js_only`): признаки по ним — только из выдачи поиска.

## Не сделано

- Чтение подтверждённого сайта и объекты с него — 25B.
- Повторная проверка уже проверенного кандидата — только новым поиском или вручную.
- Сайты отдельных ЖК как отдельные сущности: сайт ЖК подтверждается как сайт компании-застройщика.
