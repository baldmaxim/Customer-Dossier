## Блокеры безопасности до записи
1. **Цель записи.** Любая запись — только после B0: контейнер и база совпадают с `USER_RUN_CONSOLIDATED.md`, маркер и роль подтверждены,
   `backend/.env` **не** указывает на тестовую базу. При расхождении — стоп; `.env` не редактировать, маркер на незнакомую базу не ставить.
2. **Команды без preflight** (`migrate` без `--upto`, `release:check`, `release:manifest`, `pilot:check`, `npm run dev`) читают `DATABASE_URL`:
   запускать только с явной переменной окна на выделенную цель; без неё они возьмут `backend/.env` (возможно, рабочую базу).
   `npm run migrate` без явной переменной — **не запускать**.
3. **Интеграция уничтожает данные** `tg_info_test` (DROP SCHEMA на файл): сиды и копии — после B1, не до.
4. **Restore только в новую цель** `tg_info_test_restore_1019`; `tg_info_test_restore` из closure 09 не перезаписывать без проверки.
5. **Замеры и E2E пишут снимки** — не между baseline и дампом (B3).
6. **sharp**: `npm run icons:generate` и любые внешние изображения — не выполнять до A3 и решения владельца; `npm ci` во frontend — решение владельца.
7. **Сеть и модель**: `npm audit`, `npx playwright install`, `npm ci` — обращения к registry/CDN; LM Studio получает только синтетику 14A/14B; источники — только из перечня владельца.
